## 2. 產品概觀

### 2.1 定位

Peach 是本機優先的影片中繼資料擷取與媒體管理工具，一個部署只服務一個人。它沒有多人帳號、角色或租戶隔離（`SECURITY.md` 的威脅模型）。影片檔留在本機磁碟、SMB 共用或已掛載的雲端硬碟，Peach 只在帳本中記錄路徑與中繼資料。

### 2.2 主要使用情境

1. 把多處儲存位置的影片整合成一份可搜尋、可篩選的館藏，並依檔名中的番號取得標題、演員、廠牌、封面等資料。
2. 在網頁播放器或外部播放器觀看，保存字幕、速度與續播位置。
3. 追蹤創作者平台與 JAV 女優的新作，登記想要的番號，並透過雲端離線下載取得資源。
4. 整理檔案、清理重複與垃圾檔案、備份與還原帳本。

### 2.3 設計原則

| 原則 | 說明 | 依據 |
| --- | --- | --- |
| 帳本為唯一真相來源 | 應用以 SQLite 帳本中的資料為準；檔案缺失時帶個人紀錄的列標為「已消失」，不刪除 | `docs/ARCHITECTURE.md`；ADR-0087 |
| 候選須複核 | 自動取得的資料先成為候選；符合明確規則者才免複核落庫，且都可追溯、可整批撤回 | ADR-0018、0025、0052、0139、0141 |
| 線上來源只補空欄位 | 線上來源不覆蓋帳本已有的值；可覆蓋的只有官方來源與經複核的本機 NFO | ADR-0033、0035、0108 |
| 人工修改不被覆蓋 | 使用者手動改過的欄位，任何自動流程都不碰 | `docs/SOURCING.md`；ADR-0038 |
| 媒體未經要求不搬動 | 掃描與瀏覽不移動、不改名檔案；實體整理只在使用者於資料管理明確執行時發生 | ADR-0039 |
| 新檔案以推送方式進入 | 檔案系統事件與 CloudDrive2 通知為主，掃描只是後援 | ADR-0041 |
| 資料夾名稱只是候選證據 | 資料夾名稱不直接決定人物或廠牌身分 | ADR-0013 |
| 同名不等於同人 | 名稱相同不自動建立關聯或合併 | ADR-0095 |
| 遠端流量節制 | 外網請求共用 Peach 代理設定，各來源各自限流冷卻；遇 Cloudflare 或驗證牆不繞過 | `docs/SOURCING.md`；ADR-0144、0148、0160 |
| 設定彈層放值、整頁放工作 | 「一行一值、改完即存」放在偏好設定彈層；表單、長任務與危險操作放整頁 | ADR-0050 |

### 2.4 不做的事

- 不提供影片資源，也不提供付費內容的存取（README 授權段落）。
- 不引入微服務、訊息匯流排或 PostgreSQL；不一次性整站重寫前端（`docs/ARCHITECTURE.md`〈明確不做〉）。
- 不抓取或保存第三方 AI 服務的 OAuth 權杖（同上）。
- 不連接 Stash；相關轉接層已刪除（ADR-0021）。
- 不為遠端 HEVC 影片另加程式層級的轉碼回退（ADR-0016）。Peach 仍會把瀏覽器無法直接播放的容器格式（如 AVI、MKV）轉成相容的 MP4 快取（見 5.5.7）。
- 不繞過任何機器人驗證或 CAPTCHA；人機驗證須由使用者在瀏覽器完成。
- 不建議以連接埠轉發或反向代理把 Peach 放到外部網路；長期外部存取建議使用 VPN（`SECURITY.md`）。
- 不提供多人帳號、角色或租戶隔離。

## 3. 系統架構與部署形態

### 3.1 元件

| 元件 | 說明 |
| --- | --- |
| 後端 | FastAPI 模組化單體：邏輯上前後端分離，部署時是一個處理程序。路由分為 `routes_auth`、`routes_pages`、`routes_media`、`routes_configuration`、`routes_api` 五組（`docs/ARCHITECTURE.md`；ADR-0001） |
| 前端 | 單頁應用，主介面由 React 路由樹渲染，使用 Tailwind v4 與 BoardUI；建置產物提交於 `web/dist/`（ADR-0031） |
| 帳本 | SQLite，保存媒體紀錄、個人操作、資料來源與人物等檔案；全文搜尋使用 FTS5 trigram，短查詢退回 LIKE |
| 媒體引擎 | 單一 `MediaEngine`，本機檔案與掛載的雲端硬碟都是原生後端；遠端 MP4 預設走標準 Range（ADR-0014、0016） |
| 媒體工具 | FFmpeg、ffprobe、untrunc（修復損壞 MP4 索引）、人臉模型 YuNet 與 SFace、cloudflared |
| 平台層 | `peach.platform` 把帳本中的 Windows 格式路徑轉成目前系統實際讀取的路徑 |
| 擷取橋 | amane 橋接子處理程序，用於部分官方網站與社群網站（ADR-0043、0124） |
| 外部程式 | CloudDrive2（115、PikPak 等掛載與離線下載）、Prowlarr 或 Jackett（Torznab 索引器，由使用者自行設定） |
| AI Provider 邊界 | ADR-0003 規定 AI 只能產生候選，寫入真相欄位須經來源、置信度與複核；使用者介面是否提供 AI 設定：未確認 |

### 3.2 發行形態

| 形態 | 取得方式與重點 |
| --- | --- |
| Windows x64 | 完整安裝檔（含全部工具，可離線安裝）、輕量安裝檔（缺工具時先下載並驗證）、免安裝 ZIP。預設安裝到 `%LOCALAPPDATA%\Programs\Peach`，不需要系統管理員權限。測試包沒有程式碼簽章，SmartScreen 會提示，應核對 `SHA256SUMS.txt` |
| macOS | Apple Silicon 與 Intel 各一個 DMG。採 ad-hoc 簽署、未公證，下載後須移除隔離屬性。建置目標為 `MACOSX_DEPLOYMENT_TARGET=11.0`；實際最低版本文件未列明確數字，未確認 |
| Docker／NAS | 映像為 `longmeidao/peach`（Docker Hub）與 `ghcr.io/peach-mitao/peach`；標籤有版本號、`edge`、`latest`；以非 root（預設 1000:1000）執行。提供 `linux/amd64` 與 `linux/arm64` 映像，ARM NAS 實機驗收未取得 |
| 原始碼 | `git clone` 後以 uv 同步相依套件；需要 Git、uv 與 Python 3.14 以上（`pyproject.toml` 的 `requires-python >=3.14`）。Windows 以 `peach-tray.exe` 啟動，macOS 另加 `--extra macos` |
| wheel | 供持續整合驗收；`web`、`migrations`、`resources` 打包進 `peach/_resources`，以 `scripts/smoke_wheel.py` 驗收 |

Windows 與 macOS 測試包不需要另外安裝 Python、Git、Node 或 OpenSSL。版本發行與雙平台流水線屬維護者流程，本文件不展開；本 fork 的發行流程（`.github/workflows/release.yml`）與上游不同之處只有：`zhtw-build/**` 分支推送即演練並產出 Windows 與 macOS 測試包而不發布；來源快取位址取自儲存庫變數 `PEACH_SOURCE_CACHE_BASE`；不在上游儲存庫以外建置 Docker 映像（ADR-0202）；macOS arm64 使用 `macos-26` 機器；凡執行 `scripts/changelog.py --notes` 的作業都須有 OpenCC（可選依賴 `naming`），用來產生 Release 正文的繁體版本。

### 3.3 系統需求

- Windows：最低作業系統版本，文件未列，未確認。
- macOS：見上表。
- Docker：宿主機若要讀取 CloudDrive2 掛載的雲端硬碟，須為 Linux 並支援 FUSE 與 `rslave` 掛載傳播；Docker Desktop 不適用。
- 容器不讀取使用者電腦的瀏覽紀錄，也不含互動式瀏覽器；需要本機瀏覽器完成驗證的來源在容器中不可用（`docs/DOCKER.md`）。
- 媒體工具尋找順序為：環境變數、獨立程式目錄、資料目錄下的 `tools/ffmpeg/bin`、PATH。原始碼部署在 Windows x64 可於「應用與維護 → 執行資訊」按「安裝」下載；macOS 與 Linux 的原始碼部署須自行安裝。

### 3.4 資料根目錄結構

設定檔固定為 `<Peach 資料目錄>/config.toml`。資料目錄的尋找順序為：環境變數 `PEACH_DATA_ROOT`、專案目錄旁的 `peach-data/`（最多往上找四層）、未設定。預設位置：Windows 為 `%LOCALAPPDATA%\Peach\peach-data`，macOS 為 `~/Library/Application Support/Peach/peach-data`，Docker 為 `/data`（命名卷 `peach-data`）。設定值優先序為環境變數、設定檔、內建預設值。

| 子目錄 | 內容 |
| --- | --- |
| `database/` | `ledger.db` 與備份 |
| `generated/` | 可重建的產物：轉碼與串流快取、縮圖、整理備份、遠端媒體快取等 |
| `sources/` | 不可變的原始輸入（瀏覽器、追蹤、盤點與匯出） |
| `state/` | 任務檢查點、各項狀態 JSON、`storage-policy.json`、`remote-reporting*.json` 等 |
| `secrets/` | `access.json`、`browser-sessions.json`、`auth-token`、`tls/` 與各類憑證檔 |
| `logs/` | 日誌 |
| `tools/` | 本機管理的媒體工具 |
| `review/` | 複核產物 |

`docs/ARCHITECTURE.md` 另列 `archive/` 與 `inbox/`，而 `docs/OPERATIONS.md` 列的首次設定子目錄未含這兩項，兩份文件的清單不一致，列入第 9 節。

### 3.5 連接埠與健康檢查

| 項目 | 值 |
| --- | --- |
| 首次設定暫時服務 | `127.0.0.1:8900`，無 TLS，僅回送位址 |
| 原始碼部署（系統匣啟動） | HTTP 80 只負責導向，HTTPS 443；macOS 為 8443，另以 pf 轉發 80 到 8900、443 到 8443 |
| Windows、macOS 測試包 | 高位連接埠的 HTTP；「只有這台電腦」綁定 `127.0.0.1` 且不發布 mDNS，「同一個區域網路的裝置」綁定 `0.0.0.0` 並發布 `<mdns_name>.local:<連接埠>`；實際預設的連接埠號碼文件未列，未確認 |
| Docker | 容器內固定 `0.0.0.0:8900`；宿主機以 `PEACH_BIND`（預設 `127.0.0.1`）與 `PEACH_PORT` 發布 |
| 直接執行 `peach serve` | 預設只監聽 `127.0.0.1`（`SECURITY.md`）；非回送位址且沒有存取權杖時拒絕啟動 |
| `/healthz` | 不帶參數回報存活與分項狀態；`?ready=1` 另檢查設定、頁面、資料庫查詢與遷移，未就緒回 503。欄位含 `configured`、`ledger_sync`（`writer`、`reader`、`disabled`）、`media_mounts`、`mdns` |
| Docker HEALTHCHECK | 每 30 秒一次、逾時 5 秒、啟動寬限 60 秒、連續 3 次失敗判為不健康，可由 `PEACH_HEALTHCHECK_*` 調整 |

服務啟動期間資料庫遷移進行中時，`/healthz` 與 `/api/client-updates` 照常回應，其餘 `/api/` 與媒體路由回 503（`message_code` 為 `api.ledger.migrating`）。

### 3.6 寫入端與唯讀端

雙機複製由設定檔 `[replication] enabled` 控制，預設為 `false`。啟用後，同一時間只有一台電腦能修改帳本，另一台由 API 強制唯讀；帳本透過 SMB 共用上的 SQLite backup API 複製，圖片資產另以 Syncthing 單向同步（ADR-0017）。此機制屬進階與維護者用途，一般單機或 Docker 部署不需要。

使用者看得到的差異如下。

- 唯讀端只能瀏覽人工複核、追蹤管理與想要清單；寫入類操作（複核決定、新增追蹤、雲端下載等）只在寫入端可用。複核頁在唯讀端顯示寫入端的即時佇列，不可達時顯示快取。
- 唯讀端遇到尚未套用的帳本遷移時不安裝更新，須先更新寫入端。
- 系統匣會多出「同步資料庫」與「由本機接管資料庫寫入」兩項。
- 兩台電腦須使用同一份存取權杖檔，HTTPS 的本機 CA 各自獨立，mDNS 名稱須不同。

## 4. 資訊架構

### 4.1 側欄導覽

側欄入口可隱藏、上下移動，並可還原預設順序（`sidebarOrder`）。預設可見的入口共八項，順序取自前端 `DEFAULT_SIDEBAR_ORDER`。

| 入口 | 路由 | 用途 |
| --- | --- | --- |
| 首頁 | `/` | 全部館藏的卡片或列表視圖 |
| 追蹤（介面原名：关注） | `/follow` | 各來源的更新動態 |
| JAV | `/jav` | JAV 分區：館藏、探索、新作、想要 |
| 藝人（介面原名：艺人） | `/performers` | 藝人名冊 |
| 標籤（介面原名：标签） | `/tags` | 本機與線上標籤 |
| 廠牌 | `/studios` | 片商與廠牌名冊 |
| 已標記（介面原名：已标记） | `/flagged` | 已標記清單 |
| 管理 | 開啟管理選單 | 見 4.2 |

下列入口預設不顯示，可在「偏好設定 → 外觀與導覽 → 導覽入口與順序」加入側欄：播放清單 `/playlists`、沉浸模式 `/immerse`、統計 `/stats`、人工複核 `/review`、資料管理 `/data-cleanup`、資源回收筒 `/trash`、追蹤管理 `/subscriptions`、高畫質版 `/quality-goals`。人工複核、資源回收筒與高畫質版另可由資料管理頁的卡片進入。側欄底部依序為明暗切換、配色與設定。

另有不在側欄的頁面：播放牆 `/wall`、沒看過 `/unseen`、稍後看 `/watch-later`、創作者名冊 `/creators`、事務所名冊 `/agencies`、系列 `/series`、垃圾檔案 `/junk-files`、重複檔案 `/duplicates`、來源與憑證 `/sources`、登入 `/login`。

### 4.2 管理選單

管理選單的項目與順序可調整（`manageOrder`）。預設共六項，「Peach 組態」只在執行 Peach 的那台電腦上列出。

| 入口 | 路由 | 用途 |

| 統計 | `/stats` | 館藏、儲存與觀看統計 |
| 口味 | `/taste` | 由瀏覽紀錄與本機行為產生的偏好分析 |
| 資料管理（介面原名：数据管理） | `/data-cleanup` | 整理、維護、清理與刪除 |
| 追蹤管理（介面原名：关注管理） | `/subscriptions` | 追蹤列表、新增追蹤、標籤管理 |
| 任務中心（介面原名：任务中心） | `/tasks` | 背景任務與雲端下載進度 |
| Peach 組態（介面原名：Peach 配置） | `/settings/library` 起的六個分組 | 表單、長任務與危險操作 |

### 4.3 偏好設定與 Peach 組態

介面有兩層設定。偏好設定（介面原名：设置）是彈層，放「一行一值、改完即存」的偏好，共五個分組；Peach 組態是整頁，放表單、長任務與危險操作，共六個分組，且只能在執行 Peach 的那台電腦、由系統匣管理時修改（Docker 例外，見 5.14）。

| 入口 | 路由 | 用途 |
| --- | --- | --- |
| 偏好設定 → 外觀與導覽 | `/settings`、`/settings/appearance` | 主題、密度、側欄、介面語言等 |
| 偏好設定 → 瀏覽與播放 | `/settings/playback` | 播放與瀏覽偏好 |
| 偏好設定 → JAV 與新作 | `/settings/jav` | JAV 分區偏好 |
| 偏好設定 → 搜尋與推薦 | `/settings/search` | 搜尋紀錄與推薦 |
| 偏好設定 → 內容顯示 | `/settings/content` | 內容顯示偏好 |
| Peach 組態 → 媒體庫與入庫 | `/settings/library` | 媒體庫、儲存根目錄、影片預覽、番號辨識規則 |
| Peach 組態 → 來源與訂閱（英文為 Feeds） | `/settings/subscriptions` | 來源憑證、資料網站、搜尋索引器、追蹤排程 |

舊路由會轉址：`/configuration` 到 `/settings/library`，`/diagnostics` 到 `/settings/diagnostics`，`/activity` 到 `/tasks`，`/scraping` 到 `/sources`，`/follow-manage` 到 `/subscriptions`，`/resource-sync` 到 `/data-cleanup/resource-sync`。

## 5. 功能規格

以下每項功能以固定欄位說明：用途、入口、行為與規則、預設值與限制、相關設定。查不到的欄位寫「未確認」。

### 5.1 媒體庫與儲存根目錄

#### 5.1.1 媒體庫與資料夾設定

- **用途**：把本機資料夾、SMB 共用或雲端硬碟掛載資料夾加入 Peach，並歸入某個媒體庫。
- **入口**：Peach 組態 → 媒體庫與入庫（介面原名：媒体库与入库），路由 `/settings/library`。設定鍵為 `libraryFolders`、`mediaLibraries`。
- **行為與規則**：
  - 媒體庫是使用者自訂的分組，身分是持久的 UUID（`library_id`），不是名稱（ADR-0115）。一個媒體庫可含多個資料夾，作品合併顯示並共用名稱、顏色與處理方式；要分開顯示或分開設定才另建媒體庫。新增媒體庫使用獨立 ID，同名不合併。
  - 重複的資料夾與父子重疊的資料夾一律拒絕。
  - 每個資料夾須選「讀取策略」：「正常讀取」或「流量保護」。選流量保護時會限制自動讀取影片；未選讀取策略不能儲存。
  - 變更既有資料夾的實際位置須明確選「重定位此目錄，保留檔案記錄」（`change_mode: "relocate"`），帳本中的路徑前綴不變；加入另一個資料夾則取得新的身分。移除設定只移除資料夾宣告，不刪除檔案與個人紀錄。
  - 儲存媒體庫設定後 Peach 會重新啟動，並可選「儲存後掃描並補齊資料」。首次儲存路徑設定前，會先備份 `config.pre-media-identity.toml`。
  - 帳本中的影片路徑一律是 Windows 格式。macOS、Linux 與 Docker 以 `[media.locations]`（帳本中的路徑前綴）搭配 `[media.mounts]`（本機實際資料夾）對應，網頁儲存時自動處理；`PEACH_MEDIA_MOUNTS` 可暫時覆蓋，供診斷使用。
- **預設值與限制**：安裝後沒有預設媒體資料夾；網頁首次設定可稍後再加。`peach init --no-input` 產生的設定檔帶有 `local`、`115`、`pikpak` 三個範例來源（見 5.16）。
- **相關設定**：5.1.2（處理方式）、5.1.4（自動發現新檔案）、5.11.1（掃描與同步）。

#### 5.1.2 處理方式、圖示與來源色

- **用途**：決定一個媒體庫的作品要不要連網補資料，以及在介面上如何辨識。
- **入口**：同 5.1.1，每個媒體庫一組設定；設定鍵 `libraryPolicy`、`libraryIcons`、`libraryColor`。
- **行為與規則**：
  - 處理方式有三種：「自動補全」（`auto`）、「僅使用本機資料」（`local`，不連網補資料、封面與人物圖，仍讀取影片資訊並產生九宮格）、「自訂」（`stages`，可勾選：讀取影片資訊、連網補資料、連網補封面、連網補人物圖片、產生九宮格預覽）。三種都會先讀取本機 NFO 與同資料夾的圖片。
  - 定時掃描、增量入庫與重試，都按作品所屬媒體庫的處理方式執行（ADR-0116）。
  - 圖示約有 42 款（題材、身分、場景、媒介各一組）或「自動辨識」；雲端媒體庫不另選時顯示來源網站標誌，本機路徑顯示預設磁碟圖示。
  - 來源色用於卡片上區分來源，空值表示不上色。
- **預設值與限制**：預設處理方式為「自動補全」；來源色預設不上色。ADR-0116〈後續〉所列的「本次跳過／以後也跳過」、被略過步驟顯示「已跳過」、依人物所屬媒體庫細分人物圖片，尚未實作，不屬於現有功能。
- **相關設定**：5.6（中繼資料擷取）、5.5.4（影片預覽）。

#### 5.1.3 SMB 媒體來源

- **用途**：直接連接 NAS 或其他電腦的 SMB 共用資料夾，不必先掛載。
- **入口**：Peach 組態 → 媒體庫與入庫，來源選「SMB 共用」，路徑格式 `smb://host/share[/子資料夾]`；按「測試連線」驗證（`POST /api/configuration/smb/test`）。
- **行為與規則**：帳號可用 `DOMAIN\username`；可勾選「要求 SMB 加密」。密碼不回顯，憑證存於 `secrets/follow/smb-<root_id>.json`（非加密保險箱）。整理與改名限於同一個宣告根目錄內，永久刪除先隔離再提交。直接的 SMB 來源只靠掃描，不加入本機檔案監控。沒有寫入權限時讀取照常。
- **預設值與限制**：不支援 DFS、重解析點與跨共用移動。
- **相關設定**：5.1.4、5.11.2（整理檔案）。依據為 `docs/SMB.md` 與 ADR-0123。

#### 5.1.4 自動發現新檔案

- **用途**：新檔案出現時自動登記入庫，減少手動掃描。
- **入口**：Peach 組態 → 媒體庫與入庫（介面原名：自动发现新文件，設定鍵 `fileDiscovery`）；`POST /api/configuration/push-discovery`。
- **行為與規則**：選項包含發現新檔案後自動入庫、監控本機資料夾、接收 CloudDrive2 通知（Webhook，可更換密鑰）。以系統檔案事件與去抖佇列運作，不定期遍歷，網路磁碟不遞迴監控。CloudDrive2 通知端點不走一般登入，改以來源（回送位址或區域網路）、共享密鑰與雲端路徑前綴三道條件把關。登記新片或雲端下載整理完成時會跳出提示（最多晚 10 秒、3 部以上合併）。掃描登記時，若番號對上「已消失」的列，會接回該列的個人紀錄（ADR-0087）。
- **預設值與限制**：未儲存設定時，本機檔案監控預設開啟，CloudDrive 通知須另行設定。Peach 停機期間新增的檔案要靠「同步新增檔案」補齊。
- **相關設定**：5.10.3（雲端硬碟掛載與推送發現）、ADR-0041。

#### 5.1.5 離線與掛載狀態、已消失狀態

- **用途**：讓儲存位置離線或檔案消失時，館藏與個人紀錄不遺失。
- **入口**：側欄頂部的媒體庫選擇器（可切換「全部媒體庫」或單一媒體庫）；`GET /api/libraries`、`GET /api/sources`；系統匣狀態。
- **行為與規則**：
  - 掛載狀態：正常的來源每 600 秒偵測一次，異常的每 60 秒一次；首次失敗隔 1 秒複查，連續兩次失敗才確認故障。只有一個來源的全部根目錄都離線，才判定整個來源離線；播放門檻按 `root_id` 判斷。掛載故障不會觸發服務重新啟動。缺少實際資料夾時，該來源顯示離線，帳本紀錄保留。
  - 已消失：檔案不在磁碟上時，帶個人紀錄者（喜歡、評分、稍後看、播放清單、觀看歷史、尋找更好版本）標為 `asset.disposal='vanished'`，不帶者在資源同步時永久刪除。「已消失」的列在列表、搜尋、統計與推薦中視為不在庫（ADR-0087）。
- **預設值與限制**：偵測週期如上，是否可設定：未確認。
- **相關設定**：5.11.4（資源同步）、5.11.5（檔案已遺失的記錄）。

### 5.2 館藏瀏覽、搜尋與篩選

#### 5.2.1 館藏首頁與篩選

- **用途**：瀏覽全部館藏（本機磁碟加已掛載的雲端硬碟）。
- **入口**：側欄「首頁」，路由 `/`；`GET /api/items`（加 `summary_only=1` 只回傳 `total`、`bytes`、`work_total`）。JAV 館藏為 `/?jav=1`。
- **行為與規則**：首屏先讀取 `count=0` 的條目，統計與後續條目另外取得。側欄篩選包含內容標籤、追蹤標籤、時長（最短、最長分鐘）、畫幅、產地、發行年份、來源與影片屬性。發行年份支援多選（`year=2024,2023`）與未知年份（`year=none`），按發行日期而非入庫日期計算。篩選條件寫入網址，點開詳情後返回會保留篩選、捲動位置與頁碼。媒體庫以 `library` 參數（持久的 `library_id`）篩選，未知的 ID 得到空集合。
- **預設值與限制**：窄螢幕（寬度 760px 以下）時，篩選列隨捲動收合，向上捲動時恢復固定。館藏、名冊或標籤為空時，介面會給出下一步引導（新增媒體、補齊影片資料、清除篩選、新增追蹤等），而不只顯示「暫無」。
- **相關設定**：5.2.2、5.17。

#### 5.2.2 卡片與列表顯示

- **用途**：切換館藏顯示方式；首頁與各資料頁共用，瀏覽器會記住選擇。
- **入口**：館藏工具列的「卡片／列表」切換。
- **行為與規則**：列表欄位含封面、名稱、歸屬、時長、體積、觀看次數，另可顯示發行時間、入庫時間、觀看時間、解析度、觀看進度與高潮計數。排序鍵與列表欄共用，由伺服器對完整篩選結果排序。全選只影響本頁，已選項目跨頁保留，底部批次操作作用於全部已選項目。窄螢幕時，時長與體積收在名稱下方。卡片與列表的每一列可按右鍵開啟該作品的操作選單，列表另有「操作」欄（`catalog:mediaActions`，上游 `0.60.0` 的 #773）。
- **預設值與限制**：每頁預設 20 部，可選 10、20、50、100。另有卡片大小（大圖或小圖）與圖片排版（固定比例或瀑布流）兩項偏好。
- **相關設定**：偏好設定 → 外觀與導覽（`tileSize`、`density`、`photoLayout`）。

#### 5.2.3 資料夾模式與目錄樹

- **用途**：依原始資料夾結構瀏覽館藏。
- **入口**：首頁與資料頁作品區的「資料夾模式」開關；網址 `/?browse=folders`，`folder` 指定資料夾，`folder_recursive=0` 只看當前層。
- **行為與規則**：目錄樹依媒體庫頂層資料夾分組，只顯示帳本已登記的資料夾；離線掛載仍可瀏覽已登記的內容，尚未掃描的檔案與空資料夾看不到。「包含子資料夾」決定是否納入下層。麵包屑可回到祖先資料夾，「全部資料夾」回到根列表。此模式不移動也不改名任何檔案，實體整理走資料管理（ADR-0039）。
- **預設值與限制**：桌面版目錄欄寬 224px，1100px 以下改為彈層；子資料夾入口預設顯示 12 個，可「展開全部」。
- **相關設定**：5.2.4、5.11.2。

#### 5.2.4 設定資料夾用途

- **用途**：把某個資料夾對應到個人分類、人物、創作者或帳號，批次建立作品關聯。
- **入口**：資料夾模式中的「設定目錄用途」（介面原名：设置目录用途）。
- **行為與規則**：關聯類須輸入規範名稱；已有的實體或唯一別名會自動解析，有歧義時要求改用規範名稱，新名稱可在確認時建檔。必須先選「套用到子資料夾」與「新檔案沿用此規則」，再按「預覽影響」，確認後才「儲存目錄用途」；更改任一選項須重新預覽。逐件確認、檔案層級的歸屬與否定都會保留；有衝突的項目保留現有歸屬並提供「查看歸屬衝突」。「新檔案沿用此規則」只對日後登記的檔案生效，以最近一層的規則為準；「移除規則」只撤回該規則建立的關聯。資料夾名稱只作為身分的候選證據（ADR-0013）。
- **預設值與限制**：`docs/DIRECTORY_BROWSING.md` 列出五種用途（含賣家與廠牌），語系檔 `folderRule` 只有人物、創作者與分類三種用途鍵，兩者不一致，見第 9 節。
- **相關設定**：5.3（實體頁面）。

#### 5.2.5 搜尋與建議

- **用途**：以作品名、番號、藝人、廠牌或標籤搜尋館藏。
- **入口**：頂部搜尋框（提示文字「搜尋館藏」），窄螢幕須先按放大鏡。
- **行為與規則**：建議面板依種類分頁，內容含全部作品、追蹤的作者、作品與圖片、藝人與新作、JAV 推薦與搜尋紀錄（可個別刪除）。全文搜尋使用 SQLite FTS5 trigram，短查詢退回 LIKE。
- **預設值與限制**：搜尋紀錄與相關推薦可在偏好設定關閉；關閉後不讀取也不記錄，且不請求該模組。
- **相關設定**：偏好設定 → 搜尋與推薦。

#### 5.2.6 儲存的篩選、我的收藏與已標記清單

- **用途**：快速回到常用的篩選與收藏的實體。
- **入口**：篩選列讀數旁的星形按鈕開啟「我的收藏」彈窗，分頁為事務所、創作者、片商與廠牌、系列與儲存的篩選；已標記與稍後看位於導覽底部。獨立頁面為 `/unseen`（沒看過）、`/watch-later`（稍後看）、`/flagged`（已標記）。
- **行為與規則**：收藏的標籤併入「我的收藏」。儲存篩選的建立流程：未確認。
- **預設值與限制**：未確認。
- **相關設定**：5.3.2（標籤收藏）。

#### 5.2.7 列表欄位篩選與排序項目

- **用途**：在館藏列表與各種管理表格的欄位標題上直接篩選，並自訂排序項目。上游 `0.59.0` 新增（CHANGELOG #744、#754）。
- **入口**：館藏列表（`/`）的欄位標題；篩選條件寫在網址的 `column_filters` 參數。其他表格（追蹤來源與訂閱源、連結管理、系統診斷的健康清單、依女優批次刪除等）共用同一套元件（`frontend/src/react/components/table-column-filter.tsx`、`use-table-filters.tsx`）。
- **行為與規則**：
  - 多選欄位：藝人（`people`）、媒體庫（`library`）、片商與廠牌（`studio`）、標籤（`tags`）、評分（`rating`）、解析度（`resolution`）。選項可搜尋、分頁載入，提供全選與「排除」模式（只排除勾掉的值，其餘都留）。
  - 範圍欄位：體積、時長、觀看次數、高潮計數、發行日期、入庫時間、觀看時間與分數（`size`、`dur`、`plays`、`o`、`release`、`new`、`played`、`score`）。日期與時間的上限含當天，其他量為閉區間；時長的滑桿以 1 分鐘為單位，也可輸入小數分鐘（CHANGELOG #743）。
  - 離線的媒體庫在篩選選項中呈灰色。
  - 排序項目可自訂顯示與順序（`frontend/src/sort-preferences.ts`），首頁可按發行時間排序（CHANGELOG #744）。哪些頁面可自訂：未確認。
- **預設值與限制**：CHANGELOG 另列訂閱、別名、清理、複核表格也有可搜尋的欄位篩選；除上述程式可見者外，逐頁清單：未確認。
- **相關設定**：5.2.1、5.2.2。

### 5.3 實體頁面與標籤管理

#### 5.3.1 名冊與實體資料頁

- **用途**：以藝人、片商與廠牌、創作者、事務所、系列為單位瀏覽作品，並查看各實體的已記錄事實。
- **入口**：名冊 `/performers`（動畫作者用 `category=animation`）、`/studios`、`/creators`（FC2 賣家名冊）、`/agencies`、`/series`、`/tags`；資料頁為 `/performers/:id`、`/studios/:id`、`/creators/:id`、`/agencies/:id`、`/series/:id`、`/tags/:id`。
- **行為與規則**：
  - 資料頁路徑使用數字 ID，不含名字；改名沿用同一網址，被合併的 ID 會跳到最終的身分（ADR-0088）。不存在或種類不符的實體 ID 回 404。
  - 名冊可依字母表或標籤雲瀏覽，版式分「緊湊」與「大圖」，並有身分分類篩選：藝人頁有女優、素人、西方；創作者另有網黃博主、賣家、動畫作者。分類是查詢時產生的投影，一個人可同時符合多類（ADR-0095）。實體過濾在分頁之前執行。
  - 資料頁含別名、同台藝人、「訂閱新作」開關、已記錄事實（生日、出道、身材、罩杯、公司成立、母公司等）、照片分頁（官方樣張、本機圖片）、線上更新、「更改統一名稱」與「是同一個人」確認。
  - 頭像可更換，來源有備選圖庫、番號封面、作品畫面、本機檔案與網址，並可框選裁切。單張原圖與轉換結果皆不得超過 16 MiB。
  - 名稱相同不得自動建立關聯或合併（ADR-0095）。
  - 刪除檔案（上游 `0.59.0`，#738）：資料頁與名冊多選可刪除藝人、創作者、片商、事務所與系列的檔案，提供三種處理：只刪檔案並保留作品、作品移至資源回收筒、連媒體檔一併永久刪除（`web_entity_deletion.py` 的 `profile`、`trash`、`purge`）。須先預覽範圍並取得 `token`，預覽過期要重新預覽；寫入前以 SQLite 備份為 `ledger.pre-entity-delete-<批次>.db`。刪除整份檔案、整個來源或大量清理須按住按鈕約兩秒（填滿進度條，中途放開即取消）；永久刪除不可復原。
- **預設值與限制**：名冊版式與身分分類的預設值：未確認。
- **相關設定**：5.7（命名、別名與合併）、5.9.5（訂閱新作）、偏好設定的「女優名稱」（`performerNameLanguage`，六種顯示方式，見 5.17.1；存於資料庫、各裝置共用，只改變顯示，不改人物名稱或別名原文）。

#### 5.3.2 標籤瀏覽與管理

- **用途**：瀏覽本機與線上標籤，並整理重複、錯誤或不想看到的標籤。
- **入口**：`/tags`，分「本機」與「線上」兩頁；標題旁的鉛筆圖示進入管理模式，再按一次返回。API 為 `GET/POST /api/tag-management`、`POST /api/tag-management/preview`。
- **行為與規則**：
  - 瀏覽：分類有外貌身材、情境場所、人物關係、角色設定、性交體位、故事劇情、影片屬性與其他內容（線上另有角色、創作者、通用、中繼資料）；可用標籤雲或字母表；狀態分「使用中」「已隱藏」「已封鎖內容」。標籤可收藏（星形），收藏併入「我的收藏」。
  - 管理：重新命名（舊名成為別名，ID 不變）；合併（至少兩個，預覽資源數與重疊數，無法直接復原，寫入前自動以 SQLite 備份）；「整理重複標籤」（只在有重複時顯示，限於同義詞與字元寬度等確定規則）；隱藏與還原；線上標籤的「封鎖內容」與「恢復內容」。
  - 所有寫入都須先預覽並取得 `token`。維護腳本 `scripts/repair_duplicate_tags.py` 預設只輸出 CSV，寫入須加 `--apply` 與 `--backup`。
- **預設值與限制**：每頁預設 100，可選 50、100、200。
- **相關設定**：5.2.1（內容標籤篩選）、5.8（未收錄類別詞的複核）。依據為 `docs/TAG_MANAGEMENT.md`。

#### 5.3.3 手動標籤

- **用途**：為單一作品加上自己的標籤。
- **入口**：作品詳情的「新增標籤」。
- **行為與規則**：可新增、改名、刪除，成功後可復原。
- **預設值與限制**：每個作品至多 100 個手動標籤；名稱長度 1 至 80 字，不得含逗號或控制字元。
- **相關設定**：5.3.2。

### 5.4 作品詳情與個人紀錄

#### 5.4.1 詳情頁與覆蓋層

- **用途**：查看單一影片檔或單一作品的規格、歸屬與相關推薦。
- **入口**：資產詳情 `/assets/:id`（單一檔案版本）、作品詳情 `/works/:code`（以規範番號聚合多個資產，如 `/works/ABP-968`）；追蹤條目為 `/posts/:id`。
- **行為與規則**：站內的詳情連結以覆蓋層開啟，關閉後返回來源網址並保留查詢與捲動位置；按住 Ctrl、開新視窗與下載連結沿用瀏覽器行為。詳情含規格、歸屬（可開啟「未歸屬」）、產地（可為推斷值）、樣圖與預覽影片、評論（JAV）與「接著看」推薦。舊路由（`/item/:id`、`/jav/movie/:code`、`/follow/item/:id` 等）自動轉址。
  - 編輯資料（上游 `0.59.0`，ADR-0165，API `POST /api/item-edit`）：標題旁的「編輯資料」可一次改番號、標題、原題、發行日期、產地、演員、廠牌、系列與標籤；改過的欄位以使用者手動為準，之後的擷取與自動寫入不會覆蓋，刪掉的演員也不會被擷取加回。找不到的演員、廠牌與系列可當場建立，並在名冊與詳情標示「自訂」（`user_created`）。封面可改用上傳的圖片、播放器目前畫面或樣張，並可還原為擷取的封面。標籤在詳情頁為唯讀，須由編輯資料或標籤列尾端的「編輯標籤」增刪。
  - 單部重新抓取：詳情頁的「重新抓取資料」（介面原名見 `catalog:detailSource.recollect`）不使用快取，向各來源重新取這部片的資料；你改過或批准過的欄位不會被覆蓋，另一趟處理進行中時須等它結束。
- **預設值與限制**：產地推斷的規則：未確認。
- **相關設定**：5.5、5.4.3。

#### 5.4.2 版本與分卷

- **用途**：在同一作品的多個檔案間切換。
- **入口**：詳情頁的「版本」與「分卷」。
- **行為與規則**：多個檔案以「版本」（editions）與「分卷」（parts）區分；播放上下文以網址參數表達：`?editions=`、`?parts=`、`?playlist=`、`?mix=`。檔案已不在磁碟時顯示「已消失」且不可播放。
- **預設值與限制**：無。
- **相關設定**：5.1.5。

#### 5.4.3 個人評價與標記

- **用途**：記錄個人喜好，供推薦與整理使用。
- **入口**：詳情頁的操作列。
- **行為與規則**：功能有評分（1 至 5 星，可取消）、喜歡（可附喜愛理由）、不合口味（降低推薦權重）、看過了（只降低近期推薦）、記一次高潮、稍後看、尋找更好版本（高畫質、無浮水印或完整版）、加入播放清單、移至資源回收筒（檔案保留，可在回收筒永久清除）。「稍後看」是佇列意圖，與喜歡、看過分開儲存（ADR-0008）。「尋找更好版本」的目標登記在 `asset_quality_goal`，入口為 `/quality-goals`。
- **預設值與限制**：帳本中 `asset.rating` 沿用 Stash 的 0 至 100 分，五星以 20 的倍數寫入（`docs/STASH.md`）。
- **相關設定**：5.11.10（資源回收筒）、5.9.8（口味）。

#### 5.4.4 封面取景與裁切

- **用途**：讓封面以正面部分顯示。
- **入口**：詳情頁的「裁剪封面，框出正封」。
- **行為與規則**：使用者手動框選不改動原圖，並可鎖定正封比例；手動框不會被自動重算覆蓋。自動流程由人臉座標（`scripts/detect_cover_faces.py`）與正封邊車檔（`scripts/poster_crop_boxes.py`）產生；預設只重算缺少、版本過期或尺寸不符者，`--redo` 全部重算。頁面端負責最終比例，後端不預先裁成頁面形狀。
- **預設值與限制**：演算法閾值以原始碼常數為準，文件未列，未確認。
- **相關設定**：5.6.6（封面）。依據為 `docs/COVER_ARTWORK.md`。

#### 5.4.5 館藏統計

- **用途**：了解館藏規模、儲存使用與觀看習慣。
- **入口**：管理選單「統計」，`/stats`。
- **行為與規則**：內容分館藏、儲存、觀看三類（分頁的確切名稱：未確認）。可見圖表含時長分布、畫質、檔案類型、內容標籤覆蓋、標籤來源、儲存卷使用率、每日播放、播放時段、重播次數、最近看過、真實觀看與到達比例。觀看歷史熱圖支援 7、30、90、365 天與全部；`last_played` 不充當完整的播放事件序列。空狀態會導向對應功能。
- **預設值與限制**：畫質依顯示尺寸的長邊分檔：3000 以上為 4K，2000 至 2999 為 2K，1800 至 1999 為 1080P，1200 至 1799 為 720P，其餘為低畫質（`docs/OPERATIONS.md`）。
- **相關設定**：5.9.8（口味頁不在統計內）。

### 5.5 播放器

#### 5.5.1 網頁播放器與播放策略

- **用途**：在瀏覽器內直接播放館藏影片。
- **入口**：詳情頁播放器、小窗播放、沉浸模式與播放牆共用同一套播放元件（`frontend/src/player/`）；串流端點為 `/stream`。
- **行為與規則**：
  - 控制項有播放與暫停、進度、音量、靜音、全螢幕、影院模式（快速鍵提示為 T）、畫中畫、字幕、設定齒輪（清晰度、播放速度、畫面旋轉、氛圍模式）與右鍵選單（複製影片網址、複製目前時間的網址、循環播放、迷你播放器、播放統計）。已播放與剩餘時間可切換。
  - 播放策略依 ADR-0014 與 ADR-0016：`/stream` 對本機與遠端統一使用標準 Range；遠端（115、PikPak）的 `.mp4`、`.m4v` 預設直接經 `/stream` 讀取掛載檔。HLS 為選用，只有在 `/api/stream-plan?mode=hls` 且時長已知時才回傳，原因是 HEVC 包在 TS 中會造成無聲的黑畫面。伺服器端不逐檔偵測編碼，ADR-0016 也不為遠端 HEVC 另加程式層級的轉碼回退；原生容器的檔案若瀏覽器無法解碼，會得到明確的媒體錯誤。瀏覽器不支援的容器格式（如 AVI、MKV）另走「相容性轉碼」，見 5.5.7。
  - 控制列的總時長以帳本為準，帳本沒有值時才採用瀏覽器回報的值（ADR-0014）。
  - ISO 原盤會提示改用支援原盤的外部播放器；媒體資料夾無法存取時顯示原因，並可「重新整理狀態」；計費（`metered`）來源在開始拉流前，須在詳情頁確認。
  - 畫中畫按鈕在支援的瀏覽器固定佔位，載入期間停用，瀏覽器拒絕時保留原因。小窗播放在離開詳情頁後繼續，可「展開到詳情」。「播放統計」顯示緩衝健康度、連線速度、解析度、視口與影格、影片 ID 與連線階段。
  - 新手導覽期間，播放器不請求主影片串流、不自動播放、不記錄觀看。
- **預設值與限制**：自動播放與小窗等為偏好設定，預設值：未確認。懸停在卡片上的預覽，遇到需要整片轉碼且沒有快取時回 415。
- **相關設定**：偏好設定 → 瀏覽與播放；Peach 組態 → 應用與維護 → 影片播放 →「轉碼方式」，控制 5.5.7 相容性轉碼的硬體或軟體偏好（見 5.5.7）。

#### 5.5.2 播放速度、旋轉、續播與按影片保存的記憶

- **用途**：保存每部影片的播放偏好與位置。
- **入口**：播放器設定齒輪；API 為 `GET/PUT /api/player/memory?video=…`（程式另保留同義的 `/api/subtitles/memory`）。
- **行為與規則**：
  - 速度範圍 0.25 倍至 3 倍，步進 0.05，快速選項為 1、1.25、1.5、2、3 倍；旋轉為 0°、90°、180°、270°，控制列保持正向，只影響網頁畫面。這些數值取自前端常數，文件未載明。
  - 旋轉、速度、字幕選擇與字幕外觀依影片保存在伺服器的 `state/player-subtitles/<影片識別碼>/`（`subtitles.json`），詳情、小窗與沉浸模式共用，跨瀏覽器還原；設為 0°、正常速度或關閉字幕也會保存。影片識別碼為 `item:<資產 ID>`，或追蹤條目的 `follow:<貼文 ID>:<main 或序號>`。
  - 續播位置優先讀取目前瀏覽器儲存的位置，沒有才使用 `leave_ratio`；外部播放器回寫的位置不會改變已有瀏覽器紀錄的續播點。觀看統計由帳本的活動介面累計。
- **預設值與限制**：Docker 必須持久掛載資料目錄，否則這些記憶會遺失。
- **相關設定**：5.5.3、5.5.5。

#### 5.5.3 字幕

- **用途**：載入並顯示字幕。
- **入口**：播放器的字幕按鈕；`GET /api/assets/:id/subtitles`、`/api/subtitles/search`。
- **行為與規則**：
  - 字幕來源有四種：已登記的字幕；與影片同資料夾即時發現的配對字幕（不進子資料夾、不寫帳本）；使用者載入的本機檔案（SRT、ASS、SSA、VTT，轉成 WebVTT）；「搜尋中文字幕」（由 SubtitleCat 提供，可能含機器翻譯）。
  - 外觀可調整字型、字號、文字與背景與視窗的顏色和不透明度、字元邊緣樣式，並可重置。選擇與外觀依影片保存（見 5.5.2）。
- **預設值與限制**：本機字幕檔上限 4 MiB。未取得授權的媒體資料夾不參與字幕發現。
- **相關設定**：無獨立設定項；字幕搜尋會連到外部網站，受 Peach 代理設定影響（見 5.14.6）。

#### 5.5.4 影片預覽與時間軸預覽

- **用途**：在進度條上顯示縮圖，並為封面與卡片產生預覽圖。
- **入口**：播放器進度條；`GET /api/timeline?id=`、`GET /timeline?id=&s=&source=`（裁切後的 JPEG，支援 HEAD 與 ETag）。
- **行為與規則（讀取時間軸預覽）**：
  - 優先序為：與影片精確配對的既有預覽、Peach 自有的時間軸快取、九宮格、只顯示時間。讀取既有預覽不啟動 FFmpeg。詳情、小窗與沉浸模式共用同一個預覽元件。
  - 支援的既有格式：WebVTT 圖片索引、HLS 圖片播放清單、DASH 圖片軌、BIF v0（Emby、Roku、Plex 匯出）、Jellyfin Trickplay（有匯出的 `trickplay.json` 時使用精確間隔；只有 JPG 時以預設 10 秒估算並標記 `estimated: true`）。索引引用的圖片須位於影片所在資料夾及其子資料夾；不讀取絕對路徑、遠端網址、加密或位元組範圍的 HLS、直播清單、DASH SegmentList、SegmentBase 與動態清單。Peach 不自動掃描 Plex 內部資料夾；Kodi 的 `.tbn` 不算預覽。
- **行為與規則（縮圖擷取間隔設定，與上述讀取分開）**：「時間軸縮圖」設定控制 Peach 自己擷取影格的密度，選項為關閉、每 30 秒一張、每 10 秒一張，API 為 `/api/thumbnail-jobs`（僅限本機）。Jellyfin 估算所用的 10 秒預設是另一個概念，與此設定無關。
- **預設值與限制**：「影片預覽」（產生九宮格與時間軸）只處理本機磁碟上的影片，是否預設開啟：未確認。「擷取影格的解碼方式」可選「自動（硬體優先）」或軟體（`preview_acceleration`），用於封面、九宮格與時間軸；掃描、讀取 NFO 與時長探測不依賴 GPU。
- **相關設定**：Peach 組態 → 媒體庫與入庫 → 影片預覽（`videoPreviews`）與時間軸縮圖（`timelineThumbnails`）。依據為 `docs/VIDEO_PREVIEWS.md`。

#### 5.5.5 外部播放器與網路播放

- **用途**：改用電腦上的播放器，或把播放位址交給手機、VR 裝置與其他播放程式。
- **入口**：詳情頁的外部播放（介面原名：外部播放器）；`POST /api/external-playback?id=…`、`GET /external-playlist/{id}.m3u`。
- **行為與規則**：
  - 本機開啟：Windows 偵測 PotPlayer、VLC、mpv；macOS 偵測 IINA、VLC、mpv；另有「系統預設播放器」。選擇存在目前瀏覽器，介面提供「重新偵測播放器」。播放器收到原始檔，網頁播放在請求成功後暫停。開啟介面只接受本機直接連線並拒絕轉送的請求，Docker 與無桌面的部署不啟動；只接收資產 ID 與固定的播放器 ID，不接受自訂程式或路徑。STRM 檔改用網路播放位址或 M3U。
  - 網路播放：「M3U 播放清單」（下載 `.m3u`）與「網路播放位址／VR」（只顯示可複製的位址）。連結有效 6 小時，重新啟動後失效，限單一資產，不含本機磁碟路徑與長期憑證，支援 HTTP Range，傳送原始檔。產生連結與開啟播放器不計為觀看紀錄。位址的 origin 一併簽署；電腦上的 `localhost` 位址在手機上不可用，HTTPS 憑證須由外部裝置信任。
  - 觀看進度回傳：mpv（JSON IPC）、VLC（Windows，本機 HTTP 介面，使用 `127.0.0.1`、隨機連接埠與密碼）與 IINA（macOS，經內建 mpv）。位置首次前進計一次 `play_count` 與 `last_played`，連續前進累計 `play_seconds`，大幅跳轉計 `seek_count`，最後位置寫入 `leave_ratio`，播完記為 1；每 30 秒與結束時各寫一次；距片尾不到 3 秒或 mpv 回報播完，視為看完。系統預設播放器與 PotPlayer 不回傳進度（PotPlayer 只做過取證，未接入）。
- **預設值與限制**：同時最多追蹤 4 個播放器、每個最長 12 小時；啟動後 15 秒連不上即放棄，失敗不提示。VLC 開啟「只允許一個執行個體」且已在執行時不會記錄進度。macOS 的 VLC 是否回傳進度，文件未載明，未確認。
- **相關設定**：5.5.2（續播）。依據為 `docs/EXTERNAL_PLAYERS.md`。

#### 5.5.6 播放牆、沉浸模式與播放清單

- **用途**：連續觀看與保存播放順序。
- **入口**：播放牆 `/wall`；沉浸模式 `/immerse`（`id` 指定起始資產；首頁的直式影片條帶（介面原名：竖屏）也可進入）；播放清單 `/playlists`。
- **行為與規則**：
  - 播放牆為多畫面瀏覽，可拖曳或用方向鍵移動，只顯示目前篩選結果，可切換封面與影片縮圖、搜尋、展開單片（上一個與下一個、進度、分卷與版本切換、移出稍後看、開啟詳情）；沒有封面的影片以「補齊封面」引導。細部互動規則：未確認。
  - 沉浸模式為連續觀看，可標為看過、不喜歡、記一次高潮與開啟資料；隨機串流在入口會濾掉磁碟上遺失來源的影片。
  - 播放清單可保存自動產生的 Mix 或手動建立的清單。保存 Mix 會複製當時的佇列，之後不隨推薦重算；可改名、刪除、拖曳調整順序與續播。刪除播放清單不刪除檔案；永久刪除媒體時，會同步移除清單項目（ADR-0008）。
- **預設值與限制**：播放清單與沉浸模式預設不在側欄，須在偏好設定加入（見 4.1）。
- **相關設定**：5.4.3。

#### 5.5.7 相容性轉碼

- **用途**：讓瀏覽器無法直接播放的容器格式也能在網頁播放器觀看，且不改動原始檔。
- **入口**：無獨立入口，播放到此類檔案時自動觸發；偏好為 Peach 組態 → 應用與維護 → 影片播放 →「轉碼方式」（介面原名：转码方式，說明文字為「用於播放時的影片轉碼」）；API 為 `GET/POST /api/media-processing`（欄位 `playback_acceleration`，值為 `auto` 或 `software`，僅限本機請求，其他裝置回 403）。實作為 `TranscodeService`（`src/peach/transcodes.py`、`hardware_transcode.py`）。
- **行為與規則**：
  - 判斷依據：程式以副檔名判斷是否需要轉碼；`.mp4`、`.m4v`、`.webm`、`.ogv`、`.ogg` 視為瀏覽器原生容器，直接以標準 Range 經 `/stream` 播放，不經轉碼；其他容器（如 AVI、MKV）轉成相容的 MP4 快取後再播放，原始檔不被改動。第一次播放前會先探測檔案，最長 20 秒。
  - 與 ADR-0014、0016 的關係：Range 是預設的傳輸方式，HLS 為選用（見 5.5.1）；ADR-0016 的決定只是不為遠端 HEVC 影片另加程式層級的轉碼回退，並未取消對不支援容器的轉碼。轉碼也走和一般播放相同的 Range 端點（`docs/OPERATIONS.md`）。
  - 盡量不重新編碼：H.264（`yuv420p`、`yuvj420p`）影片串流直接保留，AAC 音訊直接複製，其他音訊轉成 AAC。
  - 需要重新編碼影片串流時，「自動」模式依序嘗試硬體解碼加硬體編碼、軟體解碼加硬體編碼、全軟體；選「軟體」則不使用硬體。各平台：Windows 的自動檔依序探測 NVENC、AMF、QSV 編碼，三者都不可用時以 D3D11VA 解碼再交給 libx264（AMF 只接受 AMD 顯卡上的 D3D11 裝置，Peach 按顯卡序號逐個探測）；Linux 使用第一個可用的 VAAPI 渲染節點（Docker 須映射 `/dev/dri/renderD*` 與 `PEACH_RENDER_GID`）；macOS 使用 VideoToolbox，硬體編碼以實際合成影格探測，並禁止以系統軟體編碼冒充硬體。AV1 的硬體解碼失敗時回退 dav1d 軟體解碼。管理者診斷可用 `PEACH_TRANSCODE_BACKEND`（`auto`、`software`、`nvenc`、`amf`、`qsv`、`vaapi`、`videotoolbox`）。
  - 同時最多進行 2 個轉碼或探測，單次最長 1 小時；關閉播放頁會取消對應的轉碼任務（詳情與沉浸模式帶有連線階段，結束時依階段停止轉碼）。
  - 懸停預覽：卡片懸停預覽的 `/stream` 請求不帶連線階段，無法取消。片源需要整片轉碼且沒有現成快取時，直接回 415，不啟動 FFmpeg。
  - 快取：整片轉碼副本在 `generated/transcodes/`，串流分段在 `generated/stream-segments/`；重建的檔頭 `.mp4hdr` 保留。快取可重建，再次播放時重新產生。容量超限時，自動清理依序刪除 HLS 分段、轉碼副本，最後才是可重建的縮圖；同層由舊到新，最近 10 分鐘用過的與正在寫入的檔案跳過。
  - 設定儲存後不需重新啟動，只對新任務生效；已產生的有效快取繼續使用，執行中的 FFmpeg 不會被強行中斷。
- **預設值與限制**：「轉碼方式」預設為自動（硬體優先）：`docs/OPERATIONS.md` 寫「均可選擇自動（硬體優先）或軟體」，未明載預設值，預設為何：未確認。輸出位元率只有 macOS 的 H.264 硬體編碼文件載明為 6 Mbit/s，其他平台以固定畫質參數編碼，位元率不固定。`docs/OPERATIONS.md` 一處只寫 Windows 使用 NVIDIA，另一處寫 NVENC、AMF、QSV 皆可，本文件採後者，程式中三者皆有支援。
- **相關設定**：5.5.1、5.5.4（擷取影格的解碼方式是另一個獨立偏好）、5.11.11（容量保護與快取清理）。

### 5.6 中繼資料擷取與來源鏈

#### 5.6.1 依內容類型的來源鏈

- **用途**：決定一個番號要問哪些網站、順序與何時停止。
- **入口**：資料處理（掃描與抓取，見 5.11.1）、`scripts/scrape_codes.py`、命令列 `peach process`；來源與登入狀態頁為管理區的「來源與憑證」（介面原名：来源和凭证，`/sources`）。
- **行為與規則**：
  - 內容類型只看番號形狀與本機證據，分為 `censored`（有碼）、`amateur`（素人）、`uncensored`（無碼）、`fc2`、`kmib`（韓國 MIB）、`other`、`unsure` 七類。
  - 有碼鏈：本機證據認得時走 prestige、faleno、dahlia；否則依序為 makers、r18dev、dmm、avwikidb、avbase、javbus、javdb。素人鏈：mgstage、sougouwiki、av_neme、avwikidb、avbase、javbus、javdb、r18dev。無碼鏈（證據指向一本道時）：1pondo、avbase、javbus、javdb、avsox。FC2 鏈：javdb、fc2、fc2cmadb、fc2ppvdb、javten、javarchive。
  - avwikidb（AVWikiDB 作品頁）自成一檔：素人鏈排在兩個認人 Wiki 之後，缺演員且兩個 Wiki 都沒有答案時接著問；有碼鏈排在 dmm 之後、綜合索引之前，前面的檔已給齊必填欄位就不問它；它答完不短路，綜合索引照問（與 dmm 同源，只是轉述）。無碼、FC2、`kmib`、`other`、`unsure` 都不問（ADR-0205）。
  - `kmib` 與 `other` 一家都不問，也不問封面。韓國 MIB 前綴與日本片同形，問回來的必是別部作品，只認官網 k-mib.com。
  - 官方檔逐檔成檔：該列缺的必填欄位（標題、演員、廠牌、發行日期）給齊了，就不問下一檔；綜合索引檔整檔一起問，不短路。
  - 創作者作品的檔名被讀成番號時，該列不送去刮 JAV（`catalog_rules.scrapes_as_jav`）。
- **預設值與限制**：來源鏈可用 `process_library(route_overrides='censored=r18dev,javdb')` 整條替換；類型或來源名寫錯會直接報錯。
- **相關設定**：5.6.3、5.1.2（媒體庫處理方式）。依據為 `docs/SOURCING.md`；ADR-0043、0044、0048、0059、0145、0205。

#### 5.6.2 欄位寫入規則與免複核自動落庫

- **用途**：減少人工複核，同時保護人工判斷。
- **入口**：無獨立入口，結果可在人工複核頁查看（5.8）。
- **行為與規則**：
  1. 線上來源只補帳本沒有值的欄位；取值與現值相同的候選不進佇列（ADR-0033）。
  2. 補空欄位且番號在該番號所有檔名中逐字出現時，免複核直接落庫；適用欄位為 `title`、`original_title`、`performers`、`studio`、`series`、`release_date`，`tags` 不在其中（ADR-0018、0025）。
  3. 只剩一家社群來源時也補空；社群來源不一致時取 javdb；日期式番號的發行日只認番號那一天（ADR-0034）。
  4. 分歧依來源優先序鏈結算：本機 NFO、官方來源、javdb、其他社群來源、備選來源 javbus；同一家給出兩個不同值時不結算（ADR-0038）。
  5. 備選來源（javbus）不挑戰已有的值；候選自報的番號與列上的番號對不上，整條剔除（ADR-0035）。
  6. 可覆蓋已有值的只有官方來源與本機 NFO（NFO 的範圍須再複核，ADR-0108）；標籤採聯集，一個不刪；僅兩種可撤回的規則 `adr-0139-official-replaces-verified` 與 `adr-0139-verified-tags-union`（ADR-0139、0141）。
  7. 出演者形態門檻：剪到年齡標記為止，剪完仍不像藝名的交人工（ADR-0025）；企劃名義先以本機 Wiki 快照與別名換成主藝名（ADR-0038）。
  8. 使用者手動改過（`user:`、`review:`）的欄位任何情況都不碰。
  9. 每筆自動落庫寫入 `review_decision`，`note` 記規則名稱、來源與取值，可回溯。
  - AVWikiDB 作品頁（ADR-0205）：分級為社群來源，只補空。標題、廠牌、系列、類別與片長轉載自 DMM／MGS，與官方來源同源，兩者一致不算第二家獨立印證；站方自行辨識的素人演員（`actorUnknown`）單獨不自動落庫，須素人系総合 Wiki、av_neme、av_name 其中另一家給出同一批演員才免複核；沒有任何認人 Wiki 開口時，該列的演員欄整欄進人工複核（含 MGStage 的素人名義），有 Wiki 給出不同的人則聽 Wiki。官方署名的演員照一般社群來源補空。演員不帶站上編號，編號仍由補女優資料後續任務依 ADR-0067 綁定。MGS 版有碼作品（如 ABW-358）的標題與日期不採用，日期只記為配信日。
  - 本機 NFO：有效欄位補空；XML 損壞或番號衝突時整份不作證據（ADR-0029、0108）。
  - 留給人工的只有三類：候選番號與檔名番號不符且整列僅此類、企劃名義三條路都解不出、詞表不認得的類別詞。
- **預設值與限制**：以上以最後修訂的 ADR 為準（規則由多份 ADR 疊加）。
- **相關設定**：5.8.2（自動寫入的資料與撤回）。

#### 5.6.3 來源網站、限流與冷卻

- **用途**：控制對外部網站的請求頻率與失敗處理。
- **入口**：來源與憑證頁 `/sources`（含全部來源的連線檢查）；斷網橫幅指向「網路與存取 → Peach 代理」；`GET /api/network-status`。
- **行為與規則**：
  - 已登記的來源包含 r18dev、dmm（GraphQL）、prestige、mgstage、faleno、dahlia、makers（amane 官網 29 家）、fc2club、freejavbt、airav、avsox、fc2、fc2cmadb、fc2ppvdb、javten、javarchive、1pondo、instagram、javdb、javbus、manko、sukebei、avbase、avwikidb。amane 橋以子處理程序執行，其虛擬環境可在來源與憑證頁重建。
  - avwikidb 作品頁：一次請求（`/work/<番號>/`），只讀頁面內的作品資料表；主機間隔 3 秒，冷卻鍵 `avwikidb`，補女優資料與補頭像後續任務等同一個限速器，合計仍是每 3 秒一頁。不取站方改寫的摘要與評論摘要、樣片、`/mgsimg/`、`/api/`、`/go/`，不提供封面（ADR-0205）。
  - javdb：擷取走匿名 API（三個主機輪替，間隔 0.5 秒）；三家都要求登入時，改讀 javdb.com 的搜尋與詳情頁（詳情頁主機間隔 3 秒）（ADR-0144、0148、0160）。
  - 封鎖處理：收到 403 或驗證頁時整個來源停下，首次冷卻 15 分鐘，連續再撞則加倍，上限為 6 小時（javdb、AVBase、JavBus 等來源相同；`scraping_access.SOURCES` 的 `blocked_pause`，上游 `0.59.0` 起 javdb 由 24 小時降為 6 小時，ADR-0166）；冷卻期間不記「查過沒有」。遇到 Cloudflare 或驗證牆一律不繞過；FC2PPV-DB 與 JAVten 的驗證須在本機瀏覽器完成（ADR-0060、0065）。
  - javdb 帳號：只有使用者在頁面上點開才發的讀取（庫外詳情、評論與磁力連結、查找資源、依名字搜尋藝人；`web_router.ACCOUNT_ROUTES`）才帶使用者設定的 Cookie；瀏覽器新增佇列、想要清單定時尋找、資料處理與訂閱源抓取等後台任務一律匿名取頁。頁面出現「帳號已被臨時停用」一類說明時，依頁面寫的恢復時刻暫停並標為帳號停用，不再當成出口被拒（ADR-0166）。
  - 抓取瀏覽器：遇到驗證牆的來源由本機 Chrome（沒有則 Edge）處理；「來源與憑證」的「抓取瀏覽器」可選「保留視窗」（預設，視窗在螢幕外、不搶前台）或「無視窗」（過不了驗證就暫停該來源），設定存於 `secrets/scraping-browser.json`（ADR-0171）。
  - 快照與「說過沒有」的記憶都保留 7 天；以瀏覽器取頁的來源（FC2PPV-DB、JAVten）單次請求 45 秒。
  - 斷網時：資料處理開始前先探測外網，判斷斷網就不逐站嘗試，標示「外部資料未取得：連不上外網」；恢復連線時自動對最近一次處理發起一次「重試未完成項」（唯讀端不自動）。
  - 專門來源：FC2 作品資料與封面、一本道、K-MIB 官網（`scripts/harvest_kmib.py`，`--apply` 前備份）、素人 Seesaa Wiki。逐項細節見 `docs/SOURCING.md`，本規格書未逐項展開。
- **預設值與限制**：Cookie 來源（JavDB、JavBus、FC2CMADB、Instagram）的憑證存在憑證庫，只保留該來源網域內未過期的項目。javdb 的配額按出口 IP 計算，不更換 `curl_cffi` 指紋。
- **相關設定**：5.14.6（Peach 代理）、5.13.1（來源會話）。

#### 5.6.4 自訂中繼資料來源

- **用途**：接入公開的 JSON 中繼資料介面作為額外來源。
- **入口**：來源與憑證頁的「自訂中繼資料來源」（介面原名：自定义元数据来源）；API 為 `/api/custom-metadata`。
- **行為與規則**：每個來源保存名稱、HTTPS 介面網址（須含一個 `{code}`）、番號格式（原樣、小寫、去連字號、連字號轉底線）、欄位路徑、適用內容類型（有碼、素人、韓國 MIB、待核番號）與連線方式；可試查、啟用、停用、刪除。只支援單次 GET 並回傳 JSON；不解析 HTML、不執行腳本、不處理 Cookie 或 API key。啟用的來源附加在適用類型內建來源鏈的末尾；回應中的番號須與查詢番號相符；置信度固定為 0.5，歸為未登記來源，不參與自動核准。刪除來源不刪除已存的快照與複核產物。
- **預設值與限制**：僅限公開網路的 HTTPS 443；拒絕重新導向與私有網路解析；時間預算 15 秒；回應上限 1 MiB。設定存於 `secrets/custom-metadata.json`，不寫入帳本。
- **相關設定**：5.6.1。依據為 `docs/CUSTOM_SOURCES.md`。

#### 5.6.5 番號辨識規則

- **用途**：從檔名取出番號。
- **入口**：行為內建；使用者可在 Peach 組態 → 媒體庫與入庫 → 「番號辨識規則」（介面原名：番号识别规则，設定鍵 `codePatterns`）新增規則。
- **行為與規則**：
  - 內建規則先剝除畫質前綴（HD、4K）與版本後綴（-C、-UC、-SUB），再比對；推廣網域標記一律剝除。日期式番號的分隔符屬於身分（一本道用 `_`，加勒比用 `-`）；Tokyo-Hot 為小寫 `n####`；西片以「廠牌加發行日」為身分，不是番號。版本投影為「中字」「無碼」「無碼流出」「無碼破解」。
  - 來源回傳的番號必須與查詢番號比對（`same_release_code`）；短序號前綴（如 `MCDV-24` 與 `MCDV-024`）視為兩部片（ADR-0133）。
  - 升級補修會清掉舊版從檔名誤認的番號（例如手機錄影的時間戳記），回執可整批撤回。
  - 自訂規則為每行一條不分大小寫的正規表示式，番號放在 `(?<code>…)`，存入帳本、各裝置共用，處理時只補尚未有番號的影片。
  - 掃描時取檔名第一段「廠牌加至少三位數序號」；FC2 商品號可出現在任何位置；改名但編碼變動時，掃描可按番號認回（ADR-0131）。
- **預設值與限制**：預設沒有自訂規則。Tokyo-Hot 的 `k`、`red` 兩支在 javdb 與 javbus 的寫法：未確認。
- **相關設定**：5.6.1。

#### 5.6.6 封面、高畫質封面與番號樣張

- **用途**：取得官方封面與樣張。
- **入口**：來源與憑證頁；API `/api/scraping/cover`；`scripts/fetch_jav_covers.py`；任務中心的「番號樣張抓取」。
- **行為與規則**：高畫質封面的單次任務只接受館藏命中的一個番號，最多 80 個請求、32 MiB、180 秒；只在完整圖面積更大且能完整解碼時以原子方式替換，不降低取樣；失敗不刪除既有封面。官方樣張來自 DMM／FANZA（有碼）與 MGS（素人），第一次有人檢視時才下載，失敗記一天標記（ADR-0068）；有碼作品在 DMM 沒有樣張時改取 r18.dev（CHANGELOG #717）。設定「封面」中的「沒有別的封面時用 JavDB 帶浮水印的圖」（`javdbCoverFallback`）預設關閉，官方與本機封面始終優先，之後取到不帶浮水印的封面會自動換掉（上游 `0.59.0`，#531）。
- **預設值與限制**：封面失敗的原因與年齡門的處理見 `docs/SOURCING.md`，未展開。
- **相關設定**：5.4.4（封面裁切）。

#### 5.6.7 無番號影片的聯網辨識

- **用途**：為檔名沒有番號的影片補中繼資料。
- **入口**：`scripts/identify_resources.py`（先產生工作清單，由人或智慧代理填入 CSV，再匯入）；結果進入人工複核的「資料欄位」。
- **行為與規則**：欄位限 `title`、`original_title`、`performers`、`studio`、`series`、`release_date`，來源記為 `websearch`；腳本本身不發出請求、不寫帳本。
- **預設值與限制**：僅為命令列與手動流程，沒有網頁入口。
- **相關設定**：5.8.1。

### 5.7 實體命名、別名與合併

#### 5.7.1 規範名與別名

- **用途**：讓一個人或一間廠牌在帳本中只有一個統一名稱，其他寫法成為別名，方便搜尋。
- **入口**：實體資料頁的「更改統一名稱」與別名編輯；API 為 `/api/entity-name`、`/api/entity-alias`。
- **行為與規則**：
  - 現行規則（`docs/SOURCING.md`）：規範名優先使用有出處的簡體中文通行名，暫無可靠中譯時保留日文；舊藝名、羅馬字、假名與繁體名降為別名。
  - 別名來源分三類；介面上只有使用者自己輸入的 `user:alias` 可以復原。「更改統一名稱」只能從該檔案已有的名字中選擇（`canonical_name`）。
  - 零寬字元（U+200B、U+200C、U+2060、U+FEFF）一律剝除，U+200D 保留。
  - 顯示語言由偏好設定的「女優名稱」（`performerNameLanguage`，中文、繁體中文或日文原文；繁體中文有 JavDB 繁體寫法時顯示繁體，沒有時顯示日文，ADR-0203）決定，只改顯示，不改人物名稱或別名原文。
- **預設值與限制**：本 fork 若要以繁體名稱作為規範名，現行規則與搜尋比對（`name_key()` 不做簡繁轉換）都須另行處理，此為規劃議題，尚無決定（見第 9 節）。內容資料是否隨介面語言翻譯，依 ADR-0153（狀態為「已採納，待實施」），目前未實作。
- **相關設定**：5.3.1。

#### 5.7.2 實體合併與重新導向

- **用途**：把帳本中重複的同一實體合而為一。
- **入口**：實體資料頁的「是同一個人」確認；自動合併由命名資料站的名稱欄觸發。
- **行為與規則**：
  - 合併保留作品較多的一側，遷移關係、別名、外部引用、連結與搜尋詞；舊名全部留作別名。被併入的 ID 在 `entity_redirect` 留下墓碑，舊 ID 入口（如 `/entity-image`）以 307 或解析跳到新實體；追蹤來源、訂閱源與探索關聯一併改指（ADR-0088）。
  - 合併不可逆；自動合併前會備份為 `ledger.pre-alias-merge-*.db`（ADR-0064）。自動合併僅限 minnano-av 與 av_neme 的名稱欄上同時列出兩個既有實體的情況。
  - 姓名相同不能自動合併；跨角色的身分用可撤回的 `same_person` 與 `operates_account` 關係表達（ADR-0095）。
- **預設值與限制**：合併無法復原，只能從備份還原（見 5.11.12）。
- **相關設定**：5.7.1。

#### 5.7.3 女優別名與資料的自動登記

- **用途**：自動補齊女優的別名與基本資料。
- **入口**：無獨立入口，隨追蹤檢查與資料處理的後續任務執行；批次號為 `auto:performer-alias@…` 與 `auto:performer-profile@…`。
- **行為與規則**：別名後續任務使用 minnano-av 的「別名」與 av_neme 人物頁（ADR-0055）；有 FC2 作品者先問 fc2cmadb（ADR-0061）。資料後續任務寫入 `performer_profile`（ADR-0067），avbase 為備援（ADR-0136），另有 avwikidb。出生日與身高衝突時，只記入 `metadata_json.conflicts`。可用 `scripts/revert_auto_landing.py` 整批撤回。
- **預設值與限制**：細節見 `docs/SOURCING.md`。
- **相關設定**：5.7.6（種子包）。

#### 5.7.4 頭像、廠牌標識與社群連結

- **用途**：為實體補上頭像、廠牌標誌與官網與社群連結。
- **入口**：實體資料頁；人工複核的「女優頭像」「廠牌 Logo」分類（見 5.8.1）。
- **行為與規則**：
  - 頭像來源為 r18.dev、av-wiki.net 與 Gfriends；來源門檻為長邊至少 500、短邊至少 300（這是來源門檻，不是顯示門檻）；被 Cloudflare 擋住的網站一律放棄；依臉寬挑圖並去除浮水印（ADR-0052、0056、0070、0102、0104）。
  - 廠牌以日文原名、官網與社群帳號作為標識，網站圓標與圖示合成；發行平台（FC2、myfans）不是廠牌也不是創作者（ADR-0071、0072）。
  - 社群連結來自目錄型來源（laoshi.ink、bstar-pro.com）整站抓取後離線比對名稱，由 `install_entity_links.py` 裝入；判詞為 ok、已有、conflict、未取得；X 帳號會驗證是否仍存在，「応援」粉絲號降級。
  - 事務所為 `entity.kind='agency'`，以 `entity_membership` 表示，一人只有一條現役歸屬。
- **預設值與限制**：各項細節屬頭像與標識子系統，本規格書僅列出存在，未逐項展開。
- **相關設定**：5.11.6（連結管理）。

#### 5.7.5 創作者與身分分類

- **用途**：區分頻道主與出鏡者，並支援追蹤創作者。
- **入口**：`/creators` 與創作者資料頁；追蹤管理的「創作者別名」（介面原名：创作者别名）頁。
- **行為與規則**：創作者是頻道主，不是出鏡者；輪替出演者的發行名稱是廠牌或系列。身分分類（女優、素人、西方）是查詢時產生的顯示投影，可同時符合多類（ADR-0095）。追蹤的作者落為 `creator` 實體（ADR-0096）；同名的只列出不自動建立，使用者按「是同一個人」才綁定；「創作者身分查找」的後續任務按頁面名稱到日本資料網站查詢（ADR-0098）。別名頁分為待合併與已保存的別名，可批次合併、移除與修改統一名稱。
- **預設值與限制**：無。
- **相關設定**：5.9.2。

#### 5.7.6 實體事實種子包

- **用途**：隨應用散布已核對的公開文字資料，減少重複擷取。
- **入口**：無使用者入口；匯入由任務中心自動排入；撤回為「種子批次撤回」。資料檔為 `resources/seed/entities.json`。
- **行為與規則**：
  - 內容含規範名、別名、來源編號、官網與社群連結、人物資料、事務所與廠牌關係；不含作品檔、帳本、頭像與封面。
  - 升級即取得該版本的種子；掃描與抓取結算後由任務中心自動排入匯入，應用程式啟動不觸發。只匹配本機已辨識的人物、廠牌與事務所，空的館藏不會產生他人的實體集合。人工修改與其他來源的資料受保護；套件中缺少某條資料，不代表刪除本機資料。
  - 種子登記的別名置信度至少 0.9、規範名為中文漢字且身分唯一時，採用中文規範名並同步作品署名，原名保留為別名；更名前自動備份，可由「種子批次撤回」還原（ADR-0122）。
  - 公共資料貢獻（上游 `0.59.0`，#768、ADR-0173）：選用的回饋管道，說明見 8.2 與 5.13.3。人物頁的名字選單有「貢獻中文名」，可為來源已有的日文藝名提交中文名與選填的公開參考連結，候選先存在本機；只有開啟「公共資料貢獻」後才隨每週快照送出，進入公開種子仍須維護者逐項複核，多人一致不會自動採納。
- **預設值與限制**：種子的格式 2 以 SHA-256 摘要綁定版本、修訂與累計撤銷，摘要不是數位簽章。現行種子版本號：未確認；`docs/SEED.md` 記載初始的公共複核包（`resources/seed/metadata.json`）沒有新採納的事實。
- **相關設定**：5.7.1。依據為 `docs/SEED.md`；ADR-0073、0075、0106、0117、0122、0173。

### 5.8 人工複核

#### 5.8.1 人工複核頁

- **用途**：處理自動流程無法判斷、需要人決定的候選。
- **入口**：`/review`（側欄選用入口或資料管理頁卡片）；API 為 `/api/review`、`/api/review/decision`、`/api/review/genre`。
- **行為與規則**：
  - 分類有：資料欄位（介面原名：元数据字段）、女優頭像、廠牌 Logo、創作者標籤、番號目錄存疑、FC2 評論標記、FC2 跨號相似、片尾與出處證據、西方身分回配。
  - 狀態分「待處理」「已通過」「已忽略」「稍後處理」（可恢復到待處理）；操作為「通過所選」「忽略所選」「稍後處理所選」；可依欄位、來源與來源數量分組，需要選擇來源的項目須先統一選來源。
  - 未收錄的類別詞可「收錄」為既有標籤，或判為「不是內容」。
  - 候選已過期或番號已不符時會重新判定（ADR-0079）；FC2 的描述性名稱自動拒絕。
  - 唯讀端只能瀏覽，顯示寫入端的即時佇列；寫入端不可達時顯示快取（`review_mirror`）。
- **預設值與限制**：「通過」與「忽略」的決定與批次都有留痕；經複核通過寫入的欄位（所有者標記 `review:`）受保護，自動流程不會覆蓋。
- **相關設定**：5.6.2。

#### 5.8.2 自動寫入的資料與撤回

- **用途**：檢視並撤回依規則自動落庫的結果。
- **入口**：人工複核頁「資料欄位」分類下的「自動寫入的資料」（介面原名：自动写入的资料）；API 為 `/api/review/auto-landings`、`/api/review/auto-landings/revert`。
- **行為與規則**：逐條列出 `adr-0139-official-replaces-verified` 與 `adr-0139-verified-tags-union` 仍有效的決定。撤回須先預覽，預覽會回傳計畫 `token`；實際撤回時在寫入鎖內重算並比對 `token`，對不上要求重新預覽；撤回前以 SQLite Backup API 備份；寫入後被改過或已刪除的作品保持現值。
- **預設值與限制**：其他自動落庫來源（種子、別名、樣張等）只能由腳本撤回；唯讀端拒絕撤回（ADR-0141）。
- **相關設定**：5.6.2。

### 5.9 追蹤與動態

#### 5.9.1 追蹤頁

- **用途**：集中查看各追蹤來源的更新。
- **入口**：側欄「追蹤」（介面原名：关注），`/follow`；條目詳情 `/posts/:id`。
- **行為與規則**：可依媒體類型、創作者、來源、時長與標籤篩選；排序有更新時間、時長與熱度；圖片版面為「固定比例」或「瀑布流」，另有「僅顯示圖片」。可標記已看與恢復未看；「抓更早的一頁」可回填歷史。詳情可儲存到資料庫、下載到本機、隱藏單張圖片與開啟來源頁面；追蹤條目沒有對應番號時，不提供雲端下載。
- **預設值與限制**：預設版面與排序：未確認。
- **相關設定**：5.9.2、5.9.3。

#### 5.9.2 追蹤管理

- **用途**：新增、檢查與管理追蹤來源。
- **入口**：管理選單「追蹤管理」（介面原名：关注管理），`/subscriptions`；分頁為追蹤列表、新增追蹤、標籤管理。
- **行為與規則**：
  - 新增創作者追蹤：貼上來源連結、創作者名稱或 ID；「猜你喜歡」依瀏覽紀錄中出現的次數提供來源建議，可多選批次新增。新增 JAV 訂閱源見 5.9.5。
  - 追蹤列表依創作者分組，可檢查全部、所選或失敗項，可暫停、啟用、刪除（刪除來源與已抓取的條目，媒體檔保留），可全部標記已看或已忽略，版式有表格與預設兩種。
  - 自動檢查（設定鍵 `followSchedule`）：間隔輸入範圍 15 至 10080 分鐘；近 7 天有更新的來源按設定間隔檢查，7 至 30 天乘以 3，30 至 90 天乘以 12，更久的最長每天一次；遇到限流冷卻的來源跳過，不算失敗（ADR-0134）。首次抓取範圍、頭像更新（每 3 個月）與網站圖示更新（每年）也在設定中。
  - 標籤管理支援線上標籤的分頁與批次操作（`GET /api/follow/tags`、`POST /api/follow/tag`）。
- **預設值與限制**：唯讀端僅可瀏覽。預設檢查間隔：未確認。
- **相關設定**：Peach 組態 → 來源與訂閱。

#### 5.9.3 追蹤來源與連線規則

- **用途**：說明可追蹤的平台與各自的限制。
- **入口**：追蹤管理的新增追蹤。
- **行為與規則**：
  - 已登記的來源：FANBOX、SubscribeStar、Patreon、Iwara、Kemono、Pawchive、Coomer、Rule34Video、Rule34.xxx、Rule34 Paheal、F95zone、SimpCity；另有只作為媒體來源的 Gofile。
  - 每個網站一個連接器；只在明確檢查或排程時連網，啟動與一般瀏覽不連網；不處理任何機器人驗證；只使用官方免費渠道（FANBOX 僅限 `feeRequired=0` 且 `isRestricted=false` 的內容）。
  - 憑證存於 `secrets/follow/<provider>.json`，不進快照、日誌與帳本。Rule34.xxx 只走官方 dapi，須使用者自備 API key；SimpCity 須使用者自備登入 Cookie；Iwara 的受限影片須使用者自備 `access_token`。
- **預設值與限制**：各網站的實際可用性受對方政策影響，Peach 不保證。
- **相關設定**：5.14.6（Peach 代理）。依據為 `docs/SOURCING.md`、ADR-0019。

#### 5.9.4 追蹤條目的分組規則

- **用途**：把同一創作者的連發貼文折疊成一組。
- **入口**：追蹤頁自動套用，無設定。
- **行為與規則**：同一作者內相似的標題，以「前綴加變體尾巴」歸組（至少 2 個詞、尾巴不超過 4 個詞且不含數字或 part、發布相隔不超過 7 天），於讀取時計算，不改帳本（ADR-0028）。rule34video 的連傳包須同來源、標題開頭角色名相同、站內 ID 相差不超過 30、時長相差不超過 1 秒且作品分類有交集，不同角色分開（ADR-0045）。無出處的 booru 連發須作品與角色標籤完全相同、相隔不超過 3 小時、一般標籤的 Jaccard 係數至少 0.5（ADR-0046）。booru 貼文以來源帳號為署名（ADR-0078）；再上傳靠作品特定長度連結比對（ADR-0077）。
- **預設值與限制**：以上為固定規則，無使用者設定。
- **相關設定**：5.9.1。

#### 5.9.5 JAV 訂閱源

- **用途**：自動發現追蹤中女優的新作番號。
- **入口**：藝人資料頁的「訂閱新作」開關；追蹤管理的「新增 JAV 訂閱」（介面原名：JAV 订阅源 與 添加 JAV 订阅）：輸入女優名稱，到 JavDB 演員搜尋取得卡片後勾選，可勾選多張；或使用者腳本（5.10.4）。API 為 `/api/feeds*`。
- **行為與規則**：
  - 來源為 JavDB 演員頁的偽 Feed（一頁 40 部、未發行作品先出現）與 DMM GraphQL（以女優編號取片單，預購排最前，一頁 100 部、首輪最多 200 部）；沒有編號者不建立來源。sukebei RSS 已隨 ADR-0047 清退。
  - Feed 只回答「最近出了哪些番號」：不下載、不碰媒體檔，產物是番號加作品頁網址，仍走既有來源鏈擷取。
  - 排程每 30 分鐘檢查一次誰到期，每個來源 6 小時一個視窗，並依 `id` 錯開相位（ADR-0134）；撞到冷卻時整輪只記一次失敗。合集（超大合集、單人合集、切片）可在設定隱藏（`feedCompilations`）。
  - 依名稱訂閱會新建 `performer`（來源為 `user:feed-follow`）；所勾選的卡片分屬不同人時拒絕（ADR-0083）。
  - 新作頁為 JAV 分區的 `/jav?tab=releases`，可依女優與廠牌篩選。
- **預設值與限制**：ADR-0047 的舊規則（設定頁只列已有來源、固定 6 小時）已被 ADR-0083 與 ADR-0134 修訂，不是現況。
- **相關設定**：5.9.6、5.9.7。依據為 ADR-0007、0042、0083、0134、0135。

#### 5.9.6 想要清單

- **用途**：登記尚未入庫的番號，入庫時自動對帳，並定時重新尋找資源。
- **入口**：`/jav?tab=wants`（JAV 分區的「想要」分頁），舊位址會導向此處；批次加入想要在 JAV 各分區的卡片上操作。端點清單：未確認（程式位於 `src/peach/web_wants.py`）。
- **行為與規則**：
  - 登記來源有三種：訂閱源的番號殼、追蹤條目、手動輸入的番號。使用獨立的表 `want_item`；已在庫的番號拒絕登記；與「忽略」互斥；不分 profile，全域記錄。
  - 階段為「待找」「暫時放棄」「已入庫」；「未發售」依發行日即時計算。發售 90 天內的新片一直算待找，查不到也不計次；老片查滿 3 次仍無結果，轉為「暫時放棄」，可手動「重新查找」。
  - 入庫時依番號自動對帳（批次 `auto:want-acquired@…`，可撤回）。待找支援「全部、有磁力連結、沒磁力連結」篩選。
  - 定時尋找資源（`docs/JAV_DISCOVERY.md` 與 `want_search_job`）：訂閱源每半小時檢查時順帶檢查；發售 90 天內的新片每天一次，其餘預設每週一次（可調整），來源失敗隔 6 小時；一輪最多 48 部；連續失敗 3 部或對方要求稍後再試時，該輪停止，至少間隔 1 小時；進度見任務中心「想要作品查找資源」。
  - 卡片的資源區列出磁力連結、ED2K 與網頁連結，下載仍由使用者在卡片上新增（僅寫入端可用）。資源快取：發行未滿三個月保留 7 天，更早的保留 1 年，最多 128 部，存於私有來源資料夾，不寫入帳本。
- **預設值與限制**：ADR-0090 與 ADR-0161 中關於想要清單位置與「目前不會自動重找資源」的敘述已過時，見第 9 節。
- **相關設定**：5.10.2（雲端離線下載；其「優先下載的版本」同時決定想要卡片資源區的排序）、5.10.4（使用者腳本在找不到資源時預設加入想要）。上游 `0.59.0` 起，想要清單的定時尋找間隔與放棄次數可在設定調整（CHANGELOG #661；可選值：未確認）。

#### 5.9.7 JAV 分區、探索與推薦

- **用途**：在館藏之外發現未入庫的作品，以及在館藏內找出值得看的片。
- **入口**：側欄「JAV」，`/jav`，分頁為館藏（`/?jav=1`）、探索（`/jav?tab=discover`）、新作（`/jav?tab=releases`）、想要（`/jav?tab=wants`）。
- **行為與規則**：
  - 探索有兩種範圍：「庫外發現」（`scope=external`，已知但未入庫、未忽略的作品，開啟 `/jav/movie/:code` 並轉址至 `/works/:code`）與「館藏探索」（`scope=library`，未看或只看過一次且進度不足一半的 JAV）。搜尋詞、標籤、排序、方向與範圍都存在網址中。
  - 推薦分數 = 偏好相關度 × 100；檔位 75 以上為「強烈推薦」，50 以上為「推薦」，25 以上為「值得看看」，其餘為「探索」；以 MMR 去除重複；排序可選口味、發行日期、來源評分、時長與番號。
  - 後台任務序列執行，間隔 0.5 秒，每輪最多 202 次請求、16 MiB、900 秒；固定集合至多 100 部；收到 403 或 429 即停止並冷卻。外部內容快取：作品資料在發行期間每 24 小時更新，超過一個日曆月則固定保存；圖片有三個下載槽位。
- **預設值與限制**：預設排序：未確認。
- **相關設定**：偏好設定 → JAV 與新作。依據為 `docs/JAV_DISCOVERY.md`、ADR-0103。

#### 5.9.8 口味

- **用途**：由瀏覽紀錄、書籤與本機行為產生偏好證據，供推薦使用。
- **入口**：管理選單「口味」，`/taste`；API 為 `/api/taste*`。
- **行為與規則**：
  - 偏好證據涵蓋出演者、創作者、標籤、廠牌、系列、發行區間與時長；以規則解析與統計產生，不呼叫大型語言模型。
  - 資料來源（介面原名：数据源）：自動發現 Chromium 系、Firefox 系與 Zen 等瀏覽器（Windows、macOS、Linux 各有清單，含 115、QQ、360 等）；可另外加入資料資料夾或歷史檔；書籤可匯入（Netscape HTML、Chromium Bookmarks JSON）。可「停止讀取」（已匯入的保留）或「刪除瀏覽器來源」（刪除私有庫內的歷史與書籤，不動瀏覽器原檔）。

### 5.10 資源搜尋與下載

#### 5.10.1 索引器與資源搜尋

- **用途**：依番號找出可下載的資源（磁力連結等）。
- **入口**：雲端下載對話框的「按番號查找資源」；索引器設定在 Peach 組態 → 來源與訂閱（介面原名：资源搜索，設定鍵 `indexers`，`/settings/subscriptions`）；API 為 `/api/resources/search`。
- **行為與規則**：
  - 搜尋時可設定最小與最大體積（GiB）與「優先尋找」；候選顯示番號、體積、做種數與品質，選用後按「提交下載」。
  - 直連來源（manko.fun、JavDB、sukebei）都答覆後，才可記為「無資源」；有來源沒查成（要求登入、冷卻中、連線失敗）時，按 1、5、30 分鐘自動重試，三次用完記為失敗。「未取得來源」由 `unfetched_sources` 列出。
  - 索引器為使用者在 Prowlarr 或 Jackett 設定好的 Torznab 來源。
- **預設值與限制**：最多 4 個索引器，欄位為名稱、Torznab 位址、API key 與啟用；網址不得含使用者資訊、查詢參數或片段；API key 只回報「已保存」。
- **相關設定**：5.10.2。依據為 `docs/RESOURCE_SEARCH.md`、`docs/JAV_BROWSER.md`、ADR-0161。

#### 5.10.2 雲端離線下載

- **用途**：把磁力連結交給雲端硬碟離線下載，檔案落地後自動入庫與整理。
- **入口**：JAV 入庫頁每筆作品的「搜尋資源」與「提交磁力」，高畫質版目標卡的「搜尋資源」，會在原頁開啟「雲端下載」（介面原名：云下载）對話框；進度在任務中心與活動頁的「雲端下載」段；API 為 `/api/downloads`、`/api/downloads/cancel`、`/api/downloads/postprocess`。僅寫入端可用。
- **行為與規則**：
  - 渠道：115 經 CloudDrive2 的 gRPC 提交，須有 CloudDrive2 API 權杖（至少含「提交離線任務」與「查看離線任務與配額」，取消與新建資料夾另需權限），位址留空時依序探測 `127.0.0.1:19798`、`29798`。PikPak 以非官方協定直連，可用密碼或瀏覽器登入，人機驗證由使用者在瀏覽器完成，Peach 不代為通過（ADR-0093）。光鴨等雲端硬碟僅在連接器確認支援雲端下載時，才進入渠道清單。
  - 115 每提交一次會扣一條離線配額，重新提交也算；錯誤碼 50038 判為違規，不重試，且之後拒絕同一個磁力連結。
  - 目標資料夾：115 須填 CloudDrive2 掛載樹路徑，且須落在推送發現所設的某個「雲端路徑前綴」之下；留空時可推導為該前綴之下名為「雲端下載」的資料夾（介面原名：云下载），程式內實際的資料夾名稱沿用簡體原文；資料夾不存在時須由使用者按「新建這個目錄」才建立。
  - 任務以 infohash 為冪等鍵（同一磁力連結已有任務就接手，不重送）。狀態依序為候選、已選定、已提交、遠端進行中、遠端完成、已落地、已入庫；另有旁支狀態失敗、已取消、停滯。提交時暫時無回應會顯示「等待自動重新提交」，退避 30 秒至 15 分鐘，滿 1 小時仍未送出才算失敗。
  - 後處理（ADR-0101）：只針對使用者主動提交的雲端下載，辨識正片、補番號、抓取資料，把推廣附件放進帳本的資源回收筒（不刪檔案），並套用該來源已保存的整理範本（沒有範本或沒有核驗通道則跳過）。後處理狀態 `postprocess_state` 與下載狀態分開記錄，可「重試入庫後整理」。
  - 優先下載的版本（上游 `0.60.0`，#800）：在下載渠道頁的雲端下載區拖動版本標籤排序後儲存，可選的版本為有碼、中字、無碼、無碼流出、無碼破解五種（`catalog_vocabulary.EDITION_ORDER`）。儲存後，瀏覽器新增 JAV 的一鍵入庫優先選用排在前面的版本，「想要」的資源查詢（定時尋找與卡片上的資源區）也依同一順序排序；同一版本內仍依畫質、做種數、體積等條件。手動的「查找資源」對話框走 `/api/resources/search`，程式中未見它套用此順序。沒有任何版本證據的資源視為有碼；符合不到任何已排序版本的排在後面。已設定順序時，查找不再因為某個來源已有偏好結果而提早結束（`magnet_chain.py`）。「還原預設排序」清空設定，沿用原有規則（`edition_preferences`，存於下載設定）。
  - 憑證只存在本機憑證檔，不進設定檔、不同步、不寫入日誌與資料庫。
- **預設值與限制**：等待上限預設 168 小時（設定值範圍 1 至上限小時）；停滯後每 6 小時再查看，7 天後不再查。115 每提交一次扣一條離線配額（年費 1500 條、月費 200 條）。PikPak 免費與會員帳號的離線任務上限：未確認。
- **相關設定**：Peach 組態 → 下載渠道（`/settings/downloads`）；5.9.6、5.10.3。依據為 `docs/CLOUDDRIVE.md`、`docs/CLOUDDRIVE_API.md`、`docs/RESOURCE_SEARCH.md`、ADR-0089、0093、0101、0114。

#### 5.10.3 雲端硬碟掛載、推送發現與 CloudDrive 代理

- **用途**：把雲端硬碟當作本機資料夾讀取，並在新檔案出現時立即得知。
- **入口**：Peach 組態 → 媒體庫與入庫與下載渠道；設定鍵 `pushDiscovery`、`cloudProxy`、`cloudDriveGuide`；`GET/POST /api/configuration/cloud-proxies`。
- **行為與規則**：
  - 雲端硬碟（115、PikPak、光鴨、OneDrive 與其他已掛載者）以本機資料夾形式存取。媒體讀取策略有「正常讀取」與「代理流量保護」；「產生影片預覽」另行控制九宮格與時間軸。
  - 推送發現：CloudDrive2 的 Webhook（會員功能）通知新檔案；Peach 只接受本機與私有網路的請求；可「更換密鑰」；沒設定時仍由定期全量掃描補上（ADR-0041）。
  - CloudDrive 代理：讀寫 CloudDrive2 的 API 代理與資料代理，需要「修改雲端硬碟」權限；不回顯代理密碼；設定衝突回 409。
- **預設值與限制**：快取與讀取長度為建議的起始值，並非實測最佳；CloudDrive2 的快取上限不要填 0。官方 API 已接入的範圍與待接入清單見 `docs/CLOUDDRIVE_API.md`，尚未接入的介面沒有效能結論。光鴨與 OneDrive 的真實帳號相容性：未確認。
- **相關設定**：5.1.4、5.10.2。

#### 5.10.4 瀏覽器新增 JAV 與使用者腳本

- **用途**：在外部網站的影片詳情頁一鍵加入 Peach 館藏。
- **入口**：Peach 組態 → 下載渠道的「瀏覽器新增 JAV」（`/settings/downloads`，設定鍵 `javBrowser`、`browserAdd`、`userscriptStatus`）；API 為 `/api/jav-browser*`。
- **行為與規則**：
  - 在外站詳情頁按「加入 Peach 館藏」後，Peach 依番號搜尋磁力連結，提交到預設雲端硬碟，落地後走既有的雲端下載與後處理。
  - 配對：在設定頁按「安裝 Peach 使用者腳本」、選擇預設下載渠道、「啟用並產生權杖」、「複製配對資訊」。權杖只顯示一次，伺服器端只存雜湊；專用權杖只允許查詢狀態、發起 JAV 新增與寫入受限的錯誤紀錄。「關閉瀏覽器新增」會撤銷權杖並停止尚未開始提交的佇列。
  - 進度分為排隊、搜尋、下載、入庫、整理五階段；搜尋期間可關閉頁面，佇列在重新啟動後繼續。失敗分為「磁力問題」（自動換磁力連結至多 3 次，之後可「換一個磁力」）與「雲端硬碟問題」（先檢查雲端硬碟再「重試加入」）。
  - 沒搜到資源時預設自動加入「想要」（設定鍵 `javBrowserWantOnNoMatch`，預設開啟）；腳本也可直接 `POST /api/jav-browser/want`。可恢復的網路錯誤最多自動重試 3 次（1、5、30 分鐘）。
  - 女優頁的「訂閱新作」（`/api/jav-browser/performer`）支援 JavDB 演員頁、DMM 女優片單與 MISSAV 女優頁（ADR-0143）。
  - 其他端點：`/active`（進行中的任務，最多 200 項）、`/dismiss`、`/postprocess`、`/errors`（受限的脫敏紀錄，每批最多 10 條、16 KiB）、`/identify`、`/people`、`/prioritize`、`/updates`。
  - 腳本由獨立儲存庫 peach-userscript 維護並在 Sleazy 發佈；支援網站清單的唯一來源是該儲存庫的 `jav-sites.json`，Peach 在 `web/integrations/` 保存發布快照與 SHA256 來源紀錄，執行時不下載遠端規則。
- **預設值與限制**：真實 Tampermonkey、MissAV 與 Jable 目前頁面、真實雲端硬碟下載的聯合驗收未取得。
- **相關設定**：5.10.2、5.9.5、5.9.6。依據為 `docs/JAV_BROWSER.md`、`docs/JAV_BROWSER_SITES.md`、`docs/JAV_USERSCRIPT_SLEAZY.md`、ADR-0143、0161。

### 5.11 資料管理與檔案整理

資料管理總覽（介面原名：数据管理，路由 `/data-cleanup`）分為「整理與維護」（整理檔案、媒體修復、資源同步、檔案已遺失的記錄、連結管理）與「清理與刪除」（重複檔案、垃圾檔案、資源回收筒、依女優批次刪除），並列出「待處理事項」。可刪除資料的操作各有確認與復原規則，集中整理於第 7 節。

#### 5.11.1 掃描與同步

- **用途**：把新檔案登記入庫，並補齊影片資料與預覽圖。
- **入口**：同步選單（介面原名：同步菜单）。日常同步：「同步新增檔案」「補齊待處理影片」；全庫維護：「同步所有媒體庫」「同步所選媒體庫」「僅掃描檔案」「僅補齊影片資料」「僅補齊預覽圖」「僅補齊封面」（只找缺的封面、不查影片資料，上游 `0.59.0`；略過流量保護的資料夾）。命令列為 `peach scan <來源ID> [根目錄]` 與 `peach process [location]`。
- **行為與規則**：
  - 「同步新增檔案」只列舉資料夾並補新增與待處理的影片，已知路徑跳過逐檔屬性讀取，不重複擷取，無法取代刪除檢查。
  - 啟動前顯示流量與容量預估（資料與預覽預計新增的占用、暫存峰值、各輸出磁碟的餘量，每個磁碟另留 1 GiB）；啟動視窗顯示影片檔數與可辨識的 JAV 數（預檢只按內建規則，5 分鐘內重用）。
  - 單項失敗會記入清單並繼續，結束時顯示「處理已結束，部分項目需處理」，可只重試未完成項、可「跳過這部」、可「匯出完整問題清單」（JSON）與「封存」提示。右下角進度浮窗可隱藏，並可由「顯示進度浮窗」還原。任務執行中儲存媒體庫設定須確認（會重新啟動 Peach）。
  - `peach scan` 只新增並刷新大小與修改時間，根目錄須在宣告的資料夾內；NAS 的資源回收筒、快照與系統中繼資料夾整段跳過。`peach process` 被取消時以代碼 130 結束。
- **預設值與限制**：NFO 與圖片單次讀取限時 20 秒，單部九宮格 120 秒。應用資料抓取器每趟任務向外部來源取用的總量有三道上限，哪一項先到就停，剩下的下一趟接著抓：預設 6,000 次請求、1 GiB 下載、4 小時。三項可在 Peach 組態 → 應用與維護 →「後台任務」（介面原名：背景任務）調整（`library_processing.SOURCE_BUDGET_CHOICES`，上游 `0.59.0`，#589）：每趟請求上限 1,500、3,000、6,000、12,000、24,000、48,000 次，每趟抓取時長 1、2、4、8、12、24 小時，每趟下載上限 1、2、4、8、16 GB（`sourceBudgetRequests`、`sourceBudgetHours`、`sourceBudgetGigabytes`，跟著帳本走）；設定讀不到或不在檔位內時用預設。
- **相關設定**：5.1、5.6、5.12。

#### 5.11.2 整理檔案

- **用途**：清除檔名中的裝飾符號，並可依範本改名與歸檔。
- **入口**：資料管理 → 整理（介面原名：整理文件，路由 `/data-cleanup/organize`）；API 為 `/api/organize`、`/preview`、`/apply`、`/rollback`、`/example`。
- **行為與規則**：可清除檔名裝飾符號、emoji、替代字元 `�`、私用區字元與不可見雜訊，並可選依「檔案名稱範本」與「資料夾範本」改名歸檔。必須先「預覽」再「執行整理」；更改路徑、來源或範本後須重新預覽；目標已存在則跳過。「回復上一批」可還原名稱、位置與帳本路徑。整理前會備份帳本（`generated/organize-backups/ledger.pre-organize-*.db`，保留最近 5 份）。路徑留空代表整個來源，且須屬於所選來源。
- **預設值與限制**：PikPak 的介面僅提供預覽，改名走官方核驗通道，且要求「推送發現」中該媒體根對應唯一的 CloudDrive 路徑前綴。
- **相關設定**：5.1.3、5.10.2（下載後處理使用整理範本）。

#### 5.11.3 媒體修復

- **用途**：處理卡頓或打不開的影片。
- **入口**：資料管理 → 媒體修復（`/data-cleanup/media-repair`）。
- **行為與規則**：缺時間戳表者另存修好的版本，原檔不動；缺索引者重建後替換原檔，原件改為隱藏檔保留。需要 untrunc。計費來源會警告每修一部都須整片拉取。進度顯示於資料管理頁與任務中心。
- **預設值與限制**：修復驗收只涵蓋同編碼的參照樣片，不代表任意損壞媒體都能恢復。
- **相關設定**：5.15（工具安裝）。

#### 5.11.4 資源同步

- **用途**：清除檔案已不存在的帳本紀錄、空資料夾與閒置快取。
- **入口**：資料管理 → 資源同步（`/data-cleanup/resource-sync`）；詳情頁的「同步刪除」只核對單一資料夾。
- **行為與規則**：分兩步：「檢查檔案」（唯讀，列出檔案已不在的紀錄、空資料夾、讀不了的資料夾與閒置快取）與「清理失效條目」。離線來源整個跳過；帶個人紀錄者標為「已消失」並保留，其餘永久刪除（含資源回收筒中的項目，不進資源回收筒，無法復原）。清理前逐條重新驗證；只認最近一次檢查的結果，重新啟動或再次檢查後須重來；空資料夾由下而上刪除，來源根保留；只清理目前資料目錄內的快取。每次清理留下一筆「資源同步清理」任務紀錄。
- **預設值與限制**：「同步刪除」與詳情頁的刪除動作皆可在 8 秒內復原。
- **相關設定**：5.1.5、5.11.5。依據為 `docs/OPERATIONS.md`、ADR-0036、0080、0087。

#### 5.11.5 檔案已遺失的記錄

- **用途**：處理檔案已不在但仍保留個人紀錄的作品。
- **入口**：資料管理 → 檔案已遺失的記錄（`/data-cleanup/orphan-records`）；API 為 `/api/orphan-records`、`/attach`。
- **行為與規則**：列出所有「已消失」的條目與其個人紀錄，可把個人紀錄轉移到替代檔案，或徹底刪除（不可復原）。
- **預設值與限制**：無。
- **相關設定**：5.1.5。

#### 5.11.6 連結管理

- **用途**：檢查並清除失效的官網、社群帳號與資料網站連結。
- **入口**：資料管理 → 連結管理（`/data-cleanup/links`）；API 為 `/api/links`、`/check`、`/prune`。
- **行為與規則**：「檢查失效連結」後分類結果；「刪除失效連結」會在刪除前再驗證一次，不可復原。已退隱女優的失效連結另有保留規則。
- **預設值與限制**：保留規則的細節：未確認。
- **相關設定**：5.7.4。

#### 5.11.7 重複檔案

- **用途**：找出並處理重複的影片。
- **入口**：`/duplicates`；API 為 `/api/duplicates`。
- **行為與規則**：
  - 分組：依 sha1 一致、片長推斷與同番號短版本等分組。片長、解析度與影格率都是入庫時以 ffprobe 從檔案本身量到的值，不取自線上來源。
  - 每個檔案顯示大小、片長，以及一行規格：解析度、位元率、影格率，缺值顯示「—」（本 fork 新增，在上游 `0.60.0` 的頁面之上保留）。位元率是整體位元率，以「檔案大小 × 8 ÷ 片長」計算（`web_batch._overall_bitrate`），含音訊；片長量測失敗或尚未量測時沒有位元率。組內標出最大、最長與「位元率最高」的檔案；位元率最高的標記只在至少兩個檔案有值且不全相同時出現（本 fork 新增）。
  - 手動選取（上游 `0.59.0`，#739）：每個檔案有核取方塊，也可在列的右鍵選單選取或「移至資源回收筒」；每組標題列的「回收所選 N 項」只作用於該組內已勾的檔案。確認對話框寫明檔案數、總大小與該組保留的檔案數，須按住確認鈕；移動後的回執可「復原」（還原回來）。勾選狀態只存在頁面，重新載入後清空。
  - 整組操作：每組標題列有核取方塊，勾選後畫面底部出現「所選重複組的操作」列，顯示已選組數，可對所選各組套用同一規則：留最大、留最長、優先保留 115 或 PikPak（依該組檔案所在的儲存出現）、都保留、整組回收。每組標題列也有同樣的按鈕；篩選區另有對全部組的「批次保留」。
  - 「都保留」會把該組標為已保留，不再列在待處理；切換到「已保留」檢視可「取消保留」（上游 `0.59.0`，#690）。
  - 刪除一律是「移至資源回收筒」，可還原。
- **預設值與限制**：無自動刪除。計費來源（例如 PikPak）的影片入庫時不自動量測，片長、位元率與影格率可能為空。本 fork 先前版本在頁面底部另設的跨組勾選操作列與「此組將一個都不留」提醒，隨合併上游 `0.60.0` 改用上游的手動選取機制而不再存在。
- **相關設定**：5.11.10。

#### 5.11.8 垃圾檔案

- **用途**：找出廣告附件等垃圾檔案並隔離。
- **入口**：`/junk-files`；維護腳本 `scripts/trash_junk.py`。
- **行為與規則**：涵蓋已設定的實體媒體來源（不含線上網址）；先評分再決定是否隔離；判定為垃圾只會移至資源回收筒。「不是垃圾」是可復原的逐檔判斷，會出現在「已排除」檢視。自動隔離須達自動線，並保護個人紀錄、已配對字幕、檔名自帶本片番號者與本次綁定的下載正片。
  - 視覺證據（上游 `0.59.0`，#750）：背景任務對九宮格逐格辨識推廣文字、二維碼與網域，再與時長、體積合併評分；推廣用語只出現在開頭幾格、之後持續沒有時，視為廣告片頭而受保護。視覺評分進入人工複核，沿用「不是垃圾」與撤銷；辨識引擎失敗、缺少有效測量或取樣不完整分別記錄。辨識引擎：Windows 與 macOS 用系統引擎，Linux 用 RapidOCR（`image_ocr.py`；Docker 與原始碼部署的環境準備見 `docs/OPERATIONS.md`）。證據快取在帳本旁的 `.junk-visual.sqlite3`。
  - 佇列：同名同大小的候選折疊成可展開的一組，展開後仍可逐份處理（#719）；可把目前分類中尚未決定的檔案一次移至資源回收筒（可復原，不受已載入的 200 筆限制，#218）；複核頁的「全選」涵蓋目前篩選下所有頁（#216）。
- **預設值與限制**：腳本預設只輸出候選清單；永久刪除須加 `--purge --review-csv --apply --backup`，且 `decision=delete`、信心至少 0.95。
- **相關設定**：5.11.10。

#### 5.11.9 依女優批次刪除

- **用途**：依女優永久刪除其所有關聯影片。
- **入口**：資料管理 → 批次刪除（介面原名：批量删除，路由 `/data-cleanup/batch-delete`）。
- **行為與規則**：勾選女優後，永久刪除其所有關聯影片（含資源回收筒中的項目，且不受目前篩選影響），女優檔案與照片保留；也會連帶刪除同時屬於未勾選女優的共用檔案。執行前顯示範圍與登記大小。
- **預設值與限制**：不可復原。
- **相關設定**：第 7 節。

#### 5.11.10 資源回收筒

- **用途**：暫存被移除的影片，可還原。
- **入口**：`/trash`（介面原名：回收站）；API 為 `/api/trash/empty`。
- **行為與規則**：移至資源回收筒的條目可「還原」；在資源回收筒「徹底刪除」或「清空資源回收筒」會永久刪除媒體檔與館藏紀錄，無法復原。rclone FUSE 掛載上的媒體（含飛牛 OS 原生 115 掛載的 `fuse.rclone`）會直接刪除。

- **相關設定**：5.4.3。

#### 5.11.11 儲存空間與容量保護

- **用途**：了解 Peach 的磁碟占用，清理可重建的產物，並在空間不足時保護系統。
- **入口**：Peach 組態 → 應用與維護 → 儲存空間（介面原名：存储空间）；API 為 `/api/configuration/storage`、`/measure`、`/clean`、`/policy`、`/relocate`。
- **行為與規則**：
  - 「統計占用」於背景進行，以環形圖、磁碟占用條與逐類清單顯示。可清理的類別：資料庫備份（每處保留最近一份，且目前資料庫驗證不通過時拒絕）、播放快取（`generated/transcodes/`、`generated/stream-segments/`）、縮圖（`cover-thumbs`、`avatar-thumbs`）、日誌（已封存的 `*.until-*.log` 與 `crash-*.log`）。預覽圖、封面與網路資料、匯入資料、任務與複核紀錄、媒體工具、登入狀態只統計，不清理。
  - 「更改位置」可遷移資料目錄：支援安裝版、由系統匣啟動的原始碼與無桌面服務；不可選磁碟根目錄、程式資料夾、媒體資料夾或與目前資料目錄互相包含的位置；跨磁碟須多出 1 GB 餘量；會暫停背景任務、停止服務、複製後逐項核對檔案數與大小，任一步失敗則留在原位。Docker 不提供，只列出宿主機的步驟。直接執行 `peach serve` 沒有看守處理程序，不能在設定頁遷移。
  - 容量保護（介面原名：启用容量保护，總開關為 `enabled`）：關閉時保留各項設定但停止檢查與自動清理，手動清理仍可用。欄位（整數 GiB）有磁碟保留空間（留空代表每個磁碟總量的 5%，下限 1、上限 40 GiB）、Peach 資料上限、Peach 快取上限、外部快取資料夾與上限（可由已存的 CloudDrive 位址與權杖自動讀取，需「查看系統設定」權限）；上限留空代表不限。
  - 超過餘量或上限時，自動清理依序刪除 HLS 分段、轉碼副本、可重建的縮圖（同層由舊到新，最近 10 分鐘用過的跳過）；仍超限則只暫停擷取、補修、擷取影格等會增長的背景任務，播放與瀏覽照常。統計失敗或外部快取失聯時，背景任務暫停（不把未知當成零）。預覽圖、下載的封面與資料、外部快取不自動清理；Peach 不刪除 CloudDrive 等程式的快取。
- **預設值與限制**：容量保護預設開啟，設定存於本機 `state/storage-policy.json`，不進同步帳本。文件明言目前沒有群體容量模型，不以固定百分比冒充建議值。
- **相關設定**：5.12、5.15。依據為 `docs/OPERATIONS.md`、`docs/ROUTES.md`。

#### 5.11.12 帳本備份與還原

- **用途**：手動備份帳本，必要時從備份還原。
- **入口**：Peach 組態 → 應用與維護 → 帳本備份（介面原名：账本备份）；API 為 `/api/configuration/ledger-backups`（含 `/backup`、`/restore`）；命令列 `peach migrate`。
- **行為與規則**：「立即備份」產生 `ledger.pre-manual-<時間>.db`（完整性檢查通過才命名）；清單列出所有可還原的備份（時間、來源為手動或自動與用途、大小）；「從備份還原」會先把目前帳本另存為 `ledger.pre-restore-<時間>.db`。只能在寫入端執行，且資料目錄不得有其他任務；來自較新版本的備份會拒收，較舊的先遷移；還原寫入前留下 `ledger.restore.json`，中斷後於啟動或 `peach migrate upgrade` 時續處理，結果寫入 `ledger.restore-result.json`。帳本損毀時此頁照常可用。
  - 損毀防護（上游 `0.60.0`，#806）：服務讀到 SQLite 損毀錯誤後停止帳本寫入，`/healthz?ready=1` 回 503；任務表損毀時，還原改以設定頁的進度顯示並仍檢查執行中任務的登記檔；還原通過完整性檢查後才重新允許寫入。故障期間停止的後續任務，須在還原後重新啟動服務。
- **預設值與限制**：自動備份保留規則：`ledger.pre-*.db` 保留最近幾份（預設 5 份，可在 Peach 組態 → 應用與維護 →「保留期限」選 2、5、10、20 份；`retention_settings.py`，存於本機 `state/retention.json`，不進帳本）、24 小時內與比 `ledger.db` 新者；整理備份只留最近 5 份。還原會讓資料回到備份當時的狀態。
- **相關設定**：第 7 節。依據為 ADR-0138。

#### 5.11.13 遠端媒體快取

- **用途**：說明追蹤圖片、封面與預覽圖的快取行為。
- **入口**：無使用者入口；位置為 `generated/remote-media/`。
- **行為與規則**：追蹤的圖片、封面與預覽圖在第一次讀取後永久保存；追蹤影片播放時整份保存；JAV 預覽 HLS 清單 5 分鐘後更新；遠端頭像 90 天、網站圖示與來源圖示 365 天後在下次讀取時更新，失敗時保留舊圖。沒讀取過的媒體不預先下載；中斷或長度不全的回應不安裝。瀏覽器只拿到條目與快取物件 ID，伺服端保留 HTTPS 驗證與逐跳目標檢查。
- **預設值與限制**：快取不進 Git。
- **相關設定**：5.11.11。依據為 `docs/MEDIA_CACHE.md`。

### 5.12 任務中心

#### 5.12.1 任務列表與控制

- **用途**：集中查看與控制掃描、追蹤檢查、批次操作與命令列批次處理等背景任務。
- **入口**：管理選單「任務中心」（介面原名：任务中心），`/tasks`（舊址 `/activity` 轉址至此，雲端下載進度也在此頁）；API 為 `GET /api/tasks`、`GET /api/tasks/{run_id}`、`POST /api/tasks/{run_id}/control`。
- **行為與規則**：
  - 任務狀態：排隊中、進行中、正在暫停、已暫停、正在取消、已完成、部分項目需處理、發現問題、意外中斷。觸發方式：手動、定時、啟動、命令列。
  - 控制：本機執行的任務可暫停、繼續與取消；取消會等待執行緒與子處理程序結束，已完成的結果保留，取消後不能繼續。對父任務的操作涵蓋全部後續任務；雲端下載依渠道實際能力提供控制；跨主機的任務回 403。
  - 處理速度（`set_speed`）有五檔：最慢、低占用、標準、全速、最快。Peach 組態 → 應用與維護 → 後台任務 →「預設處理速度」（`taskSpeed`）決定新任務的預設值，執行中的任務可個別調整；升級後的自動修復沿用此設定。
  - 資源標籤：CPU（藍）、GPU（紫）、網路（青）。CPU 以執行端可用容量為 100%（macOS 按原生執行緒，Linux 與 Docker 兼顧 cgroup 與 CPU 親和性）；GPU 為所屬子處理程序最忙的引擎（Windows 計數器、Linux DRM fdinfo，macOS 與無權限者顯示「未取得」）；CPU 或 GPU 達 50%、下載達 10 MiB/s 時標籤加深。
  - 斷點續跑：任務識別碼、處理範圍、完成集合與計數存於本機；服務重新啟動後接回同一筆；使用者暫停的保持暫停，明確取消的撤銷恢復。各任務的保存單位見 `docs/OPERATIONS.md` 對照表。
- **預設值與限制**：預設處理速度：未確認。
- **相關設定**：5.12.2。

#### 5.12.2 升級後自動修復

- **用途**：升級後自動完成資料庫遷移、本機確定性的資料修復與背景補齊。
- **入口**：Peach 組態 → 應用與維護 → 自動修復（介面原名：自动修复）與「修復與遷移」（介面原名：修复与迁移）；API 為 `GET /api/configuration/repairs`、`POST /api/configuration/upgrade-repairs/retry`、`GET /api/client-updates`（只讀本機快照）。
- **行為與規則**：升級後由寫入端自動完成資料庫遷移（先整份備份，頁首顯示「正在更新本機資料庫」）；失敗按退避重派，連續五次失敗後停止，可在「應用與維護 → 自動修復」重試；容量觸線時整批暫停；可下載本機複核紀錄；唯讀端不執行。修復中心每個追蹤來源保留最近 3 份快照。
  - 「修復與遷移」頁（`/settings/maintenance/repairs`，上游 `0.59.0`，#723）依種類分五組：館藏檔案、作品資料、人物與廠牌、追蹤／新作與想要、下載與任務紀錄。等待你確認的修復可「全部開始」或「開始這一組」，依序執行；會更改帳本的項目先備份帳本、可從帳本備份還原，會刪除快照的項目不能恢復。被延後的影片會顯示數量與原因，只剩延後項時標為「已延後」而非進行中；路徑無法辨識的影片直接失敗並說明原因，不再每半小時延後（CHANGELOG #734）。
- **預設值與限制**：無。
- **相關設定**：5.11.11、5.11.12。依據為 ADR-0126、0154。

### 5.13 診斷與遠端回報

#### 5.13.1 系統診斷頁

- **用途**：檢查系統狀態、館藏健康度與來源連線狀況。
- **入口**：Peach 組態 → 系統診斷，`/settings/diagnostics`（舊址 `/diagnostics` 轉址至此）；API 為 `GET /api/diagnostics`。
- **行為與規則**：
  - 系統檢查分組：設定與存取、資料庫與遷移、媒體庫與掛載、背景任務、工具。狀態有正常、需處理、需檢查、待複查、未設定、尚無紀錄。
  - 「庫健康」列出辨識失敗、補資料失敗、缺封面、缺時長四類，每類最多回傳 500 筆並保留總數，可開啟作品或複製清單。
  - 來源會話顯示 minnano-av 與 javdb 上次成功的時間與冷卻截止；開啟診斷頁不會發起抓取。
  - 「匯出擷取紀錄」最多 20 個番號，留空則取近期作品；合併後超過 100 MiB 時只留摘要。
- **預設值與限制**：無。
- **相關設定**：5.6.3。

#### 5.13.2 診斷報告與日誌

- **用途**：產生可提供給維護者的脫敏診斷檔。
- **入口**：系統診斷頁的「下載診斷報告」；系統匣「匯出診斷報告」；獨立包 `Peach.exe --diagnostic-report`；原始碼 `python -m peach.support_bundle`；Docker `docker compose exec peach python -m peach.support_bundle /tmp/peach-support.zip`。API 為 `/api/diagnostics/bundle`、`/api/diagnostics/exports`。
- **行為與規則**：診斷報告為脫敏的 ZIP，含版本、系統資訊、選定日誌的末段與可取得的系統檢查；不含設定檔、憑證、資料庫、Cookie 與媒體。於背景產生，可取消。桌面部署的下載限於本機；Docker 允許已登入的私有網路用戶端，並拒絕代理轉送。
- **預設值與限制**：日誌位於 `logs/`（`errors-<PID>.log`、`crash-<PID>.log`、`tray.log` 等），預設保留半年（Peach 組態 → 應用與維護 →「保留期限」可選 30、90、183、365 天，`retention_settings.py`），超過自然月即封存為 `*.until-<日期>.log`；回應標頭 `X-Peach-Error-ID` 與日誌關聯。瀏覽器錯誤端點 `POST /api/diagnostics/client-error` 僅限同源本機、每分鐘 20 次、每次 16 KiB。日誌固定使用英文是 ADR-0159 的決策，分階段實施。
- **相關設定**：5.13.3、5.16（`peach doctor`）。依據為 `docs/DIAGNOSTICS.md`。

#### 5.13.3 遠端回報（版本統計、錯誤診斷、館藏與口味上傳）

- **用途**：說明 Peach 會向外送出什麼、預設值與關閉方式；完整比較見第 8 節。
- **入口**：Peach 組態 → 應用與維護 → 資料上傳（介面原名：数据上传，設定鍵 `dataSharing`）；安裝器與首次設定頁也有同一個選項。
- **行為與規則**：
  - 「發送版本統計與錯誤診斷（推薦）」（介面原名：发送版本统计与错误诊断（推荐），`reportErrors`）：單一選項同時控制版本統計與錯誤診斷，預設勾選。選擇存於 `state/remote-reporting.json`，API 為 `POST /api/configuration/remote-reporting`。傳輸經 Sentry 託管服務；接收端 DSN 由維護者於建置時寫入，缺少 DSN 時頁面明示不會發送。每機每天最多登記 20 個新診斷鍵、上傳 5 條首次錯誤事件。傳輸回執狀態為 `queued`、`accepted`、`failed`、`unknown`。
  - 「上傳館藏與口味明細」：獨立選項，預設關閉。須先在本機產生預覽並明確同意；使用一次性的預覽憑證（10 分鐘有效）；每機每個 UTC 週最多送出一次。API 為 `/api/configuration/library-sharing`、`/preview`。
  - 「公共資料貢獻」（介面原名見 `settings:seedSharing`，上游 `0.59.0`，ADR-0173）：第三個獨立選項，預設關閉，入口在同一區（`/settings/maintenance#seedSharing`）；與館藏口味研究的授權互不影響。須先在本機預覽實際內容並明確同意，再每週送出一次；API 為 `/api/configuration/seed-sharing`、`/preview`。是否可用取決於接收端是否已設定（沒有接收端時顯示「未設定資料接收端」）；本 fork 自行打包的版本是否設定接收端：未確認。
- **預設值與限制**：見第 8 節。
- **相關設定**：ADR-0109、0110、0112、0113、0157。

### 5.14 帳號、存取與遠端連線

Peach 沒有帳號體系，存取控制以兩套彼此獨立的憑證為核心：存取密碼供瀏覽器登入，存取權杖供腳本與 API。

#### 5.14.1 存取密碼

- **用途**：決定用瀏覽器開啟 Peach 時是否需要登入。
- **入口**：首次設定頁或 Peach 組態 → 網路與存取 → 存取密碼（介面原名：访问密码）；登入頁 `/login`；API 為 `POST /api/configuration/access`、`POST /api/configuration/access/first`。
- **行為與規則**：可以留空，留空代表能連到 Peach 的裝置不需登入即可進入。修改須輸入目前的密碼，關閉另須勾選確認存取範圍；修改或關閉立即生效，其他瀏覽器的登入失效，目前裝置保持登入 30 天。登入頁的「保持登入」為 30 天，不勾選最長 12 小時。以 scrypt 雜湊存於 `secrets/access.json`，不進資料庫、不同步。沒有 `access.json` 的舊部署，登入頁改用存取權杖。
- **預設值與限制**：長度 8 至 256 字元；同一來源每分鐘最多嘗試登入 10 次。Docker 全新資料卷可用 `PEACH_ACCESS_PASSWORD` 預設密碼，且 Peach 沒有初始密碼（ADR-0149）。
- **相關設定**：5.14.2、5.14.5。依據為 `SECURITY.md`。

#### 5.14.2 已登入的裝置

- **用途**：檢視並撤銷已登入的瀏覽器。
- **入口**：Peach 組態 → 網路與存取 → 已登入的裝置（介面原名：已登录的设备）；API 為 `GET /api/configuration/access/sessions`、`POST .../revoke`。
- **行為與規則**：列出每個登入過的瀏覽器（瀏覽器與系統、來源網段、最近活動；目前瀏覽器標為本機）。在執行 Peach 的電腦上可「撤銷」單一裝置，或「撤銷其他裝置」。只儲存登入權杖的摘要與網段（`secrets/browser-sessions.json`）。
- **預設值與限制**：撤銷限於執行 Peach 的電腦。
- **相關設定**：5.14.1。

#### 5.14.3 存取權杖

- **用途**：供腳本與 API 呼叫使用。
- **入口**：Peach 組態 → 網路與存取 → 存取權杖（介面原名：访问口令）；命令列 `peach token`；API 為 `POST /api/configuration/access/token/rotate`。
- **行為與規則**：請求標頭使用 `X-Token`（`?t=` 僅限一次性場合）。權杖存於 `secrets/auth-token`。網頁的「更換權杖」立即生效，新權杖只顯示一次；`peach token --rotate` 須重新啟動才生效。以 `--token` 或 `PEACH_TOKEN` 指定時，網頁不能更換。啟用雙機複製時，兩台須使用同一份權杖檔。
- **預設值與限制**：`peach serve` 在非回送位址且沒有權杖時拒絕啟動（ADR-0142）。
- **相關設定**：5.16。

#### 5.14.4 HTTPS 憑證與信任

- **用途**：讓其他裝置以 HTTPS 連到原始碼部署的 Peach。
- **入口**：Peach 組態 → 網路與存取 →「其他裝置信任 HTTPS 憑證」（介面原名：其他设备信任 HTTPS 证书）；API 為 `GET /api/configuration/certificate`。
- **行為與規則**：原始碼部署以本機自簽 CA 簽發 HTTPS 憑證（`secrets/tls/`，伺服器憑證效期 397 天；Windows 上私鑰禁用權限繼承）。此頁提供 CA 憑證的 SHA-256 指紋、到期日、下載，以及行動裝置掃描的 QR Code（10 分鐘有效，重新啟動後作廢，只下載公開憑證）。
- **預設值與限制**：Windows 測試包在區域網路使用 HTTP，不加密。macOS 的系統代理可能攔截 `.local`，須把 `*.local` 等加入例外清單。
- **相關設定**：5.14.6。依據為 ADR-0142。

#### 5.14.5 外部網路入口（Cloudflare）

- **用途**：在沒有 VPN 時，經 Cloudflare 隧道從外部網路連到 Peach。
- **入口**：Peach 組態 → 網路與存取 → Cloudflare 外部網路入口（介面原名：Cloudflare 公网入口，設定鍵 `remoteAccess`、`cloudflareTunnel`）；命令列 `peach tunnel [start|status]`；API 為 `POST /api/configuration/tunnel`。
- **行為與規則**：預設關閉，必須先設定存取密碼才能啟動。模式有臨時連結（`https://<id>.trycloudflare.com`，重新啟動即換位址）與命名隧道（僅原始碼部署，權杖只寫入設定檔的 `[tunnel] token`，頁面不再顯示）。cloudflared 須能對外連線 TCP 與 UDP 7844。整個站台的每個回應都帶 `X-Robots-Tag: noindex, nofollow, noarchive`，`/robots.txt` 為 `Disallow: /`，無法關閉。
- **預設值與限制**：`SECURITY.md` 不建議以連接埠轉發或反向代理放到外部網路，長期外部存取請用 VPN。
- **相關設定**：5.14.1。

#### 5.14.6 存取位址與 Peach 代理

- **用途**：顯示可連線的位址，並設定 Peach 對外連線所用的代理。
- **入口**：Peach 組態 → 網路與存取 →「存取位址」（介面原名：访问地址）與「Peach 代理」；API 為 `POST /api/configuration/peach-proxy`、`GET /api/network-status`、`POST /api/network-status/check`。
- **行為與規則**：存取位址顯示本機位址、手機連線位址與備用 IP；Windows 測試包可選本機或區域網路並修改區域網路名稱（mDNS 名稱），儲存後重新啟動並跳轉到新位址。Peach 代理可選跟隨環境、直接連線或自訂（HTTP 或 SOCKS）；已有的任務與長連線沿用建立時的設定；個別來源可另選「直接連接」。
- **預設值與限制**：Docker 填入回送位址會提示。首次設定頁的選項為「跟隨環境／直連／自訂」。
- **相關設定**：5.6.3、5.15.1。

#### 5.14.7 Peach 組態的修改權限

- **用途**：說明誰可以修改 Peach 組態。
- **入口**：Peach 組態各分組；API 前綴為 `/api/configuration/*`。
- **行為與規則**：只在執行 Peach 的那台電腦上、且服務由系統匣管理時可修改（Docker 例外）；依連線兩端的 IP 判斷是否為本機。「選擇資料夾」在執行 Peach 的電腦彈出系統對話框（`/api/pick-folder`）；NAS 與 Docker 改用網頁內的伺服器端資料夾選擇器（只列子資料夾、不越過媒體根、不跟隨符號連結、單次最多 500 筆、逾時 10 秒）。儲存會把舊檔備份為 `config.previous.toml` 並重新啟動本機服務。Docker 的設定頁要求登入，且來源須為容器本機或私有網路；攜帶代理轉送標頭的管理請求會被拒絕。
- **預設值與限制**：原始碼部署的連接埠固定；Windows 測試包可修改連接埠並檢查衝突。
- **相關設定**：5.14.1。依據為 `docs/OPERATIONS.md`、ADR-0050。

### 5.15 安裝、更新與解除安裝

#### 5.15.1 首次設定

- **用途**：全新機器第一次開啟時的初始化。
- **入口**：系統匣啟動後自動開啟瀏覽器；Docker 全新資料卷；API 為 `GET /api/setup/questions`、`POST /api/setup`、`POST /api/setup/restore`。終端機版為 `peach init`（見 5.16）。
- **行為與規則**：
  - 只在資料目錄沒有 `config.toml` 且沒有資料庫時出現。四步精靈：歡迎、媒體資料夾、存取範圍、確認。問題含媒體資料夾（按媒體庫分組，可稍後再加）、資料目錄、存取範圍（只有這台電腦，或同一個區域網路的裝置）、Peach 代理（跟隨環境、直連、自訂）、存取密碼（選填，8 至 256 字元）、是否立即掃描與診斷回報。
  - 守衛：已設定回 404；非回送來源回 403；Origin 不符回 403；設定檔已存在回 409。
  - 「使用已有資料」：填入原資料目錄，須含有效的 `config.toml` 與資料庫（`POST /api/setup/restore`），失敗回 400 並在 `errors.data_root` 說明原因。
  - 第一頁可選介面語言（「自動」或已登記的語言），選後該頁立即切換；新建帳本時寫入同步設定（`POST /api/setup` 的 `interface_language`），接到已有帳本時不改（上游 `0.59.0`，#709）。
  - 完成後右下角出現安裝教學（館藏、抓取憑證、瀏覽器紀錄、追蹤、追蹤憑證、複核），每項可略過，進度只存在目前瀏覽器。
  - Docker：全新資料卷以 `serve --setup` 監聽，只接受宿主機或私有網路的來源（ADR-0149）。
- **預設值與限制**：安裝與首次設定流程中沒有年齡確認步驟（見第 8 節）。表單欄位的完整清單：未確認。
- **相關設定**：5.1.1、5.14.1。依據為 `docs/OPERATIONS.md`。

#### 5.15.2 開機自啟與系統匣

- **用途**：讓 Peach 在登入電腦後自動啟動，並提供常用的快速操作。
- **入口**：Peach 組態 → 應用與維護 → 開機自啟（介面原名：开机自启，API `POST /api/configuration/startup`）；系統匣圖示選單。
- **行為與規則**：
  - 選項：「開機後啟動 Peach」「只啟動系統匣，不開啟網頁」（靜默啟動）「在桌面建立捷徑」。
  - Windows：以目前使用者「啟動」資料夾中唯一的 `Peach.lnk` 達成；系統匣是唯一的日常處理程序擁有者（ADR-0011），並有獨立監控程式在意外結束時以 2、5、10 秒延遲重新啟動，5 分鐘內至多 3 次；選單結束、更新與解除安裝不觸發。
  - macOS：LaunchAgent `io.github.longmeidao.peach.tray`，`KeepAlive = {SuccessfulExit = false}`、`ThrottleInterval = 30`；崩潰與強制結束會被拉起，選單結束、登出與已有執行個體時不拉起；開機自啟關閉時沒有恢復機制。
  - 系統匣選單項目：打開 Peach、重新打開設定頁、Peach 組態（介面原名：配置 Peach）、狀態（逐服務列出，附提醒數）、位址、查看完整設定、同步開發進度、同步資料庫、由本機接管資料庫寫入、重新啟動服務、查看日誌、匯出診斷報告、版本與更新（檢查更新）、結束 Peach。
- **預設值與限制**：Docker 不使用系統匣。
- **相關設定**：5.15.3。

#### 5.15.3 檢查更新與自動更新

- **用途**：取得新版本。
- **入口**：Peach 組態 → 應用與維護 →「檢查更新」與「自動更新」（介面原名：检查更新、自动更新）；API 為 `GET/POST /api/configuration/automatic-updates`、`GET /api/configuration/updates`、`GET /api/configuration/update-status`、`POST /api/configuration/update`、`/update-restart`；更新公告為 `GET/POST /api/release-notice`。
- **行為與規則**：
  - 版本檢查只讀取本 fork（`mosesmoon/peach_zhTW`）的 GitHub 公開發行紀錄，取最高的可下載版本；不查上游儲存庫與上游下載站（ADR-0202）。fork 沒有任何發行或 GitHub 回 404 時，結果是「沒有可下載的版本」，不下載任何東西；GitHub 回 403、429、5xx 或連線失敗時回報檢查失敗，不改問其他來源。能被更新器接受的發行須使用 `vX.Y.Z` 標籤與既定的資產檔名（見 ADR-0202）。
  - Windows 獨立包：下載更新包或完整包；`release_signing.PUBLIC_KEYS` 非空時先驗證 `SHA256SUMS.txt` 的 Ed25519 簽章（ADR-0137）。**本 fork 的 `PUBLIC_KEYS` 為空**：上游 `0.60.0` 起內建的是上游自己的公鑰，本 fork 沒有對應的私鑰，合併時改回空值（見該檔案的註解與 ADR-0202 的 2026-11-21 修訂），所以 fork 的更新不驗簽章，摘要取自 GitHub 資產的 `digest`；上游文件所說「帶公鑰的客戶端只裝驗得過的版本」只適用於上游的發行。下載只有 fork 的 GitHub Release 一個來源，失敗即停；新程式通過啟動檢查後才恢復背景任務，安裝失敗會還原程式、資料庫、設定與任務檢查點。
  - macOS：本 fork 停用應用內的 Sparkle 更新，因為更新清單須以上游持有的私鑰簽署；改為版本檢查後提示下載 fork 發行的本機架構 DMG，手動替換。
  - 更新說明：上游 `0.60.0` 起，檢查到新版本時只列每個較新版本的「重點」，連同相關 issue 連結，不列完整變更（完整變更在 Release 頁）；最多列 10 版（`release_updates.NOTES_LIMIT`），來源安裝、Docker 與已是最新版時不顯示用不到的安裝包（CHANGELOG #663）。每版有 `en`、`zh-CN`、`zh-TW` 三份 `{title, text}` 清單：`zh-TW` 取自 Release 正文在完整變更連結之後、折疊的「繁體中文」段裡的「重點」分組（`scripts/changelog.py` 產生正文時以 OpenCC 自簡體段轉成），沒有該段或該分組時回落為簡體清單（`changelog_notes`、`release_words.py`）。更新清單的快取規則為 `source-aware-v4`。
  - 升級後的公告（`release_notices.py`，ADR-0152）：`0.60.0` 一則（優先下載的版本，5.10.2）；`0.59.0` 四則（館藏篩選 5.2.7、編輯作品資料與封面 5.4.1、逐份處理重複檔案 5.11.7、貢獻女優中文名 5.7.6）。
  - 自動更新設定：自動檢查新版本、自動下載更新（安裝前會詢問）、檢查頻率每 6 小時、每天或每週；需由系統匣管理的服務；不會自動下載並安裝。唯讀端遇到尚未套用的遷移時不安裝，須先更新寫入端。minor 以上版本須附更新公告（ADR-0152）。
- **預設值與限制**：首次未設定時每天檢查；其餘預設值（是否預設開啟自動下載、更新通道名稱）：未確認。
- **相關設定**：5.15.4。

#### 5.15.4 Docker 部署與更新

- **用途**：在 NAS 或 VPS 以容器執行 Peach。
- **入口**：`compose.yaml` 與 `.env`；NAS 設定產生器 `python -m peach.nas_setup`；Peach 組態 → 應用與維護，容器內顯示安裝方式為「Docker 映像」（介面原名：Docker 镜像）；API 為 `POST /api/configuration/docker-update`。
- **行為與規則**：
  - 資料卷 `/data` 必須持久；媒體掛載為 `/media`（預設唯讀）。環境變數有 `PEACH_MEDIA_ROOT`、`PEACH_BIND`、`PEACH_PORT`、`PEACH_UID`、`PEACH_GID`、`PEACH_ACCESS_PASSWORD`、`PEACH_VERSION`、`PEACH_TRANSCODE_BACKEND`、`PEACH_VAAPI_DEVICE`、`PEACH_RENDER_GID`、`PEACH_HEALTHCHECK_*`、`PEACH_LOG_*`。
  - 本 fork 不發布映像，也不比對任何映像儲存庫：容器內查到 fork 的新版本時只顯示「映像尚未發布」，不提示拉取，也沒有一鍵更新（ADR-0202）。`compose.yaml` 與 NAS 設定產生器裡的映像名稱仍是上游的，照它們部署得到的是上游映像。以下是上游映像的更新機制：版本號標籤已推送且 `edge` 指向同一映像才算有新版。未啟用一鍵更新時列出 `docker compose pull` 與 `docker compose up -d` 兩步；可選的 `watchtower` profile 提供「一鍵更新」（Watchtower 掛載宿主機的 Docker socket，等同宿主機 root 權限）。15 分鐘內未見新版會提示查看日誌。不自動回退；回復須停止服務、以 `ledger.pre-migrate-<時間>.db` 取代 `ledger.db` 並固定 `PEACH_VERSION`（ADR-0140）。啟動時若有待執行的遷移，會先備份再遷移，最多等 180 秒。
  - 映像不提供多人帳號或租戶隔離；容器設定頁要求登入，且攜帶代理轉送標頭的管理請求會被拒絕。
- **預設值與限制**：Compose 預設只綁定 `127.0.0.1`，NAS 須設定 `PEACH_BIND`。提供 `linux/amd64` 與 `linux/arm64` 映像，ARM NAS 實機驗收未取得；Docker Hub 的真實拉取與 Docker Desktop 以外的 Linux 宿主機驗收亦未取得。
- **相關設定**：5.14.7、5.11.11（Docker 不提供「更改位置」）。依據為 `docs/DOCKER.md`、ADR-0105、0140、0149。

#### 5.15.5 解除安裝與媒體工具

- **用途**：移除 Peach，或安裝所需的媒體工具。
- **入口**：Peach 組態 → 應用與維護 →「解除安裝 Peach」（介面原名：卸载 Peach，`POST /api/configuration/uninstall`）與「執行資訊」（介面原名：运行信息，`POST /api/configuration/media-tools`）。
- **行為與規則**：解除安裝僅限 Windows 測試包；預設保留資料，勾選「完全解除安裝」才刪除設定、本機資料庫、觀看紀錄、憑證與快取；原始媒體檔任何情況都保留；失敗時 `peach-uninstall.log` 在暫存資料夾。原始碼安裝與 macOS 須手動移除（先關閉開機自啟並結束）。執行資訊頁顯示版本、作業系統、設定檔、日誌資料夾與工具狀態，Windows x64 的原始碼部署可一鍵安裝 FFmpeg 與 untrunc，並連到 `/settings/diagnostics`。
- **預設值與限制**：完全解除安裝不可復原。
- **相關設定**：第 7 節。

### 5.16 命令列

#### 5.16.1 `peach` 與 `peach-tray`

- **用途**：以終端機初始化、啟動、掃描與診斷。
- **入口**：`peach` 對應 `peach.error_reporting:cli_main`，`peach-tray` 對應 `peach.error_reporting:tray_main`（`pyproject.toml`）。
- **行為與規則**：

| 子命令 | 用途與重點旗標 |
| --- | --- |
| `init` | 首次初始化。無參數為互動問答（資料目錄、本機媒體資料夾、存取範圍、連接埠、區域網路位址；每題 Enter 取預設，連續三次無效即結束且不寫檔；結束問「現在掃描？」）；有任何參數、`--no-input` 或非 TTY 則為非互動。旗標有 `--data-root --host --port --mdns-name --mount local=/mnt/media --writer-origin --writer-proxy --shared-root --smb-host --smb-share --smb-user --from-existing --force` |
| `serve` | 啟動 FastAPI：`--host --port --db --token --docs --setup --no-auth --no-mdns --no-ledger-sync --mdns-name --mdns-address --ssl-certfile --ssl-keyfile --redirect-origin --shared-db`。非回送位址缺權杖即拒絕啟動；`--no-auth` 僅限回送位址；`--host` 為回送位址時不發布 mDNS |
| `scan` | 掃描單一來源資料夾（只新增、可續跑） |
| `process` | 館藏處理 |
| `token` | 顯示或產生存取權杖，`--rotate` |
| `tunnel` | Cloudflare 隧道 `start`、`status`，`--timeout` |
| `migrate` | `status`、`upgrade --yes`；非寫入端拒絕遷移；遷移前自動備份 |
| `status` | 唯讀：帳本、遷移與同步狀態 |
| `check-sources` | 來源連通檢查（`--source`、`--json`），最多 4 個來源並行；連通不代表登入有效 |
| `doctor` | 本機診斷（`--json`、`--host`、`--port`），不執行遷移或修復 |
| `ledger-sync` | 立即同步帳本，`--take-ownership` |
| `local-image`、`media-read` | 內部子處理程序入口，一般不直接使用 |

  - `init` 在已有設定檔時拒絕並以代碼 3 結束，`--force` 才覆寫且先備份為 `config.toml.bak`；已有資料庫不重建，並提示改用 `--from-existing`（只寫設定檔）。設定檔語法錯誤時 `serve`、`migrate`、`status` 拒絕執行並報出行號；`[media]` 下直接以磁碟機代號為鍵的寫法會被拒絕。
  - `doctor` 逐項檢查版本、設定、資料庫遷移、工具、資料目錄寫入、媒體掛載、連接埠與最近任務失敗；有 `failed` 時代碼為 1，`warning` 與 `unknown` 為 0。`check-sources` 有目標未通過時代碼為 1。
  - 另有 `python -m peach.nas_setup`、`python -m peach.support_bundle`、`python -m peach.server`（無桌面服務，Docker 入口）與 `scripts/*`（維護者腳本，預設只列計畫，`--apply` 才寫入）。
- **預設值與限制**：輸出語言跟隨系統語言（中文系統顯示中文，其餘顯示英文），`PEACH_LANGUAGE=zh-CN|en` 可指定（ADR-0159）；目前不支援 `zh-TW`（見第 6 節）。`init --no-input` 產生的設定檔帶 `local`、`115`、`pikpak` 三個範例來源，而網頁首次設定則不預設媒體資料夾。
- **相關設定**：5.14.3、5.15.1。依據為 `docs/OPERATIONS.md` 與 `src/peach/cli.py`。

### 5.17 外觀與介面語言

#### 5.17.1 外觀與個人偏好

- **用途**：調整介面外觀、導覽與顯示方式。
- **入口**：側欄底部的設定，進入偏好設定彈層（`/settings/appearance` 等五個分組）。
- **行為與規則**：偏好分組為外觀與導覽、內容顯示、JAV 與新作、瀏覽與播放、搜尋與推薦。可確認的外觀項目：深色或淺色主題（`theme`）、卡片密度（大圖或小圖，`tileSize`、`density`）、側欄光暈配色與參數（`sidebarGlow`、`glowPreset`，17 種預設）、側欄順序與隱藏（`sidebarOrder`）、管理選單順序（`manageOrder`）、圖片版面（固定比例或瀑布流，`photoLayout`）、SFW 快速鍵（`sfwShortcut`，在輸入框外隨時開關）、排序文字（`sortOrder`）、「女優名稱」（`performerNameLanguage`，存於資料庫、各裝置共用；`docs/OPERATIONS.md` 寫在「JAV 與新作」）。多數偏好在儲存後即時生效（ADR-0050）。
  - 「女優名稱」六種顯示方式（`web_settings.NAME_LANGUAGE_CHOICES`、`frontend/src/core/entity-names.ts`；也套用於創作者名稱）：中文化（譯名，`zh-CN`）、繁體中文（`zh-TW`，本 fork 新增）、日語原文（`ja`）、英文（羅馬音，`en`）、日語原文（本地語言，`ja-local`）、本地語言（日語原文，`local-ja`）。選繁體中文時，有 JavDB 繁體寫法就顯示繁體，沒有就顯示日語原文，不把簡體名逐字轉繁體（ADR-0203）。「本地語言」跟介面語言走：簡體介面是譯名，日文介面是原文，其餘介面是羅馬音；繁體介面是 JavDB 的繁體寫法（`zh_tw`），沒有繁體寫法時退回日語原文。兩種並排時，相同或取不到的一種省略，中文介面用全角括號。缺少對應寫法時一律退回原文。只改顯示，不改名稱、別名與作品署名。
- **預設值與限制**：`performerNameLanguage` 沒選過時存為空（API 回 `null`），預設值依各裝置的介面語言決定（`effectiveNameLanguage`）：繁體介面（含「自動」判成繁體）為 `zh-TW`，其餘為 `zh-CN`，不回寫；選過的值不再更動。`interfaceLanguage` 預設為 `auto`。其餘各項外觀偏好的預設值：未確認。
- **相關設定**：5.2.2、5.17.2。

#### 5.17.2 介面語言

- **用途**：選擇介面顯示的語言。
- **入口**：偏好設定 → 外觀與導覽 → 介面語言（介面原名：界面语言，設定鍵 `interfaceLanguage`）。
- **行為與規則**：選項為「自動」加上已登記上線的語言；現況為 `zh-CN`（简体中文）、`zh-TW`（繁體中文，本 fork 新增）與 `en`（English）。選擇存於共享設定，跟著資料庫走，各裝置讀同一份；後端只放行已登記的語言。更換語言後整頁重新載入。詳細規則見第 6 節。
- **預設值與限制**：預設為「自動」。
- **相關設定**：第 6 節。

#### 5.17.3 新手教學與導覽

- **用途**：引導第一次使用的人完成基本設定。
- **入口**：右上角的指南針圖示；Peach 組態 → 應用與維護 → 新手教學（介面原名：新手教程）→「重新打開」。

### 6.3 與上游設計的差異及待決議題

- ADR-0156 規定登記第三種語言時改為按語言拆分、動態載入語言資源。本 fork 沒有這樣做，三種語言都打進主程式包，主程式包因此變大。
- ADR-0156 與 `CONTRIBUTING.md` 規定其他語言的譯文經 Weblate 回流、目錄名用 `zh-Hant`。本 fork 以腳本自 `zh-CN` 產生 `zh-TW`，不經 Weblate；這份成果定位為 fork 自用。
- 規範名目前優先採用簡體中文通行名，且搜尋比對的 `name_key()` 不做簡繁轉換（`docs/SOURCING.md`）。正體介面下，演員等名稱仍以簡體顯示，以正體字搜尋名稱可能比對不到。是否處理尚無決定（見第 9 節）。
- 上游 `0.60.0` 新增的空 `zh-Hant` 等語言目錄不接入：本 fork 的 `zh-TW` 由腳本產生，不使用 `zh-Hant`，也不改名或併入它；上游的 `zh-Hant` 日後若有譯文並登記為介面語言，另行決定（ADR-0201 的 2026-11-21 修訂）。
- 英文術語表 `en.tbx` 的來源語言標記為簡體中文；本 fork 的台灣用詞規則另存於 `scripts/zh_tw/terms.json`，沒有 TBX 格式的 `zh-TW` 術語表。

## 7. 危險操作一覽

下表集中列出不可復原或影響大的操作。「確認方式」欄只寫文件與程式可證實的內容；ADR-0050 規定，需要確認對話框的危險操作一律放在整頁而不是設定彈層。確認對話框的實際文字：未確認。

| 操作 | 影響範圍 | 確認方式 | 復原方式 |
| --- | --- | --- | --- |
| 資源同步清理（5.11.4） | 永久刪除檔案已不在的紀錄（含資源回收筒中的項目）、空資料夾與閒置快取；帶個人紀錄者只標為「已消失」 | 先「檢查檔案」（唯讀）再「清理失效條目」；清理前逐條重新驗證；只認最近一次檢查結果 | 刪除的紀錄無法復原；留下「資源同步清理」任務紀錄。若先前有備份，可依 5.11.12 還原帳本 |

## 8. 隱私與資料外送

Peach 的定位是本機優先：影片、帳本、個人紀錄與憑證都存在本機。除下列項目外，Peach 只在使用者明確操作、排程或所設定的功能需要時連到外部網站。

### 8.1 預設開啟的回報

| 項目 | 內容 |
| --- | --- |
| 名稱 | 「發送版本統計與錯誤診斷（推薦）」（`reportErrors`） |
| 預設值 | 開啟（預設勾選）。單一選項同時控制版本統計與錯誤診斷 |
| 送出的內容 | 版本、系統資訊、故障類型、程式碼位置與發生次數（設定頁說明文字）。診斷鍵由脫敏的技術欄位計算，包含版本，排除每次 HTTP 錯誤編號與技術實例標識 |
| 限額 | 每機每天最多登記 20 個新診斷鍵、上傳 5 條首次錯誤事件；額度不足的推遲到後續檢查或隔日補傳 |
| 傳輸 | 經 Sentry 託管服務；接收端 DSN 由維護者建置時寫入，缺少 DSN 時頁面明示不會發送 |
| 關閉位置 | 安裝器、首次設定頁，以及 Peach 組態 → 應用與維護 → 資料上傳；選擇存於 `state/remote-reporting.json`。測試包在驗收時顯式關閉 |
| 回執 | `queued`、`accepted`、`failed`、`unknown`，存於 `state/remote-reporting-delivery.json` |

接收端位址不寫在原始碼裡，由建置時的環境變數提供；自行由本 fork 打包而未設定該變數時，頁面顯示「上傳服務未設定」，不會送出任何資料，也不會送到上游。此選項是「推薦並預設勾選」，與「本機優先」的定位並存；它並非一定會發出資料（缺少 DSN 時不發送），使用者可隨時關閉。不會因為關閉而影響本機診斷：診斷報告與日誌仍可在本機匯出（5.13.2）。

### 8.2 預設關閉的上傳

| 項目 | 內容 |
| --- | --- |
| 名稱 | 「上傳館藏與口味明細」 |
| 預設值 | 關閉，開關始終可見，與技術診斷各自獨立 |
| 送出前 | 須先在本機產生預覽，檢視實際欄位與內容後明確同意；預覽不是發送，也不會開啟上傳；預覽使用一次性憑證（10 分鐘有效） |
| 送出的內容 | 館藏與口味的統計明細；不傳帳號、檔名、路徑、媒體、網址或逐筆瀏覽紀錄 |
| 頻率與大小 | 每機每個 UTC 週最多送出一次；原始 JSON 上限 100 MiB、gzip 後 18 MiB；欄位版本 6、同意範圍版本 5 |
| 關閉位置 | Peach 組態 → 應用與維護 → 資料上傳 |

另有第二個預設關閉、獨立同意的選項「公共資料貢獻」（5.13.3、ADR-0173）：開啟前須在本機預覽並同意；每週最多送出一份候選快照（每 UTC 自然週一次，重新啟用不重置次數）。內容為作品公開欄位與欄位來源、人物與廠牌的公開來源編號與抓取別名、人工修改的公開欄位與詞表內的手動標籤、標籤對應決定、封面的公開引用與手動裁切（只含圖片摘要、尺寸與座標，不傳圖片）、來源命中與未收錄等狀態，以及使用者主動提交的女優中文名；不含影片、圖片位元組、檔名、路徑、憑證、評分與觀看紀錄，無法安全投影的值不送並在預覽計數。資料經獨立的研究接收專案傳送到 Sentry，接收服務會接觸連線 IP；關閉只停止後續傳送，已接收的資料不會撤回；進入公開種子須維護者逐項複核。

### 8.3 其他會連到外部的行為

這些行為不屬於回報，但使用者應知道：

- 中繼資料擷取：依來源鏈連到各資料網站（5.6.3）。所有外網請求共用「Peach 代理」設定。
- 檢查更新：只讀取本 fork 的 GitHub 公開發行紀錄（5.15.3）；不連上游儲存庫、上游下載站與 Docker Hub。
- 字幕搜尋：連到 SubtitleCat（5.5.3）。
- 追蹤檢查、JAV 訂閱源、探索與想要清單的尋找資源：僅在排程或明確操作時連網（5.9）。
- 雲端下載：經 CloudDrive2 或 PikPak 連到雲端硬碟服務（5.10.2）。
- 口味：原始網址與標題只存在本機私有的歷史庫，不進帳本，也不隨上傳送出（5.9.8）。

### 9.2 未確認事項

**部署與系統**

- Windows 最低作業系統版本；macOS 實際最低版本。
- Windows 與 macOS 測試包預設監聽的高位連接埠。
- 各項偏好設定的預設值（自動播放、小窗、名冊版式、預設排序、卡片密度、預設處理速度等）。
- 更新通道名稱與預設值；自動更新是否預設自動下載（只確認不會自動下載並安裝）。
- 現行實體種子包的版本號。
- 掛載狀態偵測週期是否可設定。
- 首次設定表單欄位的完整清單。

**館藏與播放**

- 儲存篩選的建立流程；統計頁分頁的確切名稱。
- 列表欄位篩選與可自訂排序項目實際涵蓋哪些頁面（5.2.7）；編輯資料中標籤欄位的完整規則。
- 播放牆的細部互動規則。
- 「轉碼方式」設定的預設值；轉碼輸出位元率在 macOS 以外平台的實際值。
- 產地推斷的規則；封面裁切演算法的閾值。
- macOS 上 VLC 是否回傳觀看進度。

**來源、下載與追蹤**

- Tokyo-Hot 的 `k`、`red` 兩支在 javdb 與 javbus 的寫法。
- Instagram 獨立登入會話的行為。
- PikPak 免費與會員帳號的離線任務上限。
- 光鴨與 OneDrive 的真實帳號相容性。
- 搜狗舊版歷史格式的時間欄位語意（目前不支援）。
- 預設追蹤檢查間隔；連結管理中已退隱女優的保留規則細節。
- 想要清單相關端點的完整清單；想要清單的定時尋找間隔與放棄次數可選的檔位。
- 公共資料貢獻（5.13.3）在本 fork 自行打包的版本中是否已設定接收端。

**介面語言與在地化**

- Windows 安裝程式的多語系與香港、新加坡改用英文的處理未編譯驗證。
- 正體字型在各瀏覽器的實際顯示與分段下載行為。
- 正體介面下規範名與搜尋比對的處理方式。

### 9.3 已知限制

- 單人自架，沒有多人帳號、角色與租戶隔離。
- 真實 Tampermonkey、MissAV 與 Jable 目前頁面、真實雲端硬碟下載的聯合驗收未取得。
- ARM NAS 實機、Docker Hub 真實拉取與 Docker Desktop 以外的 Linux 宿主機驗收未取得。
- 尚未實作的 ADR 後續項目不屬於現有功能，包括 ADR-0116〈後續〉所列的「本次跳過／以後也跳過」、「已跳過」顯示與依人物所屬媒體庫細分人物圖片，以及 ADR-0153 的內容譯文。
- Windows 測試包沒有程式碼簽章；macOS 測試包未公證。
- PotPlayer 與系統預設播放器不回傳觀看進度。
- Docker 無互動式瀏覽器，也不讀取使用者電腦的瀏覽紀錄；需要本機瀏覽器完成驗證的來源在容器中不可用。
